# UI/UX 改版 · 变更记录（Phase 00 → 07）

按阶段倒序。每一条都尽量写成**用户能观察到的东西**，工程细节只在它解释了
「为什么这样写」时出现。所有数字都来自对应阶段的实测记录，出处见各 PHASE 文档。

## Phase 07 · 终审与交付

### 修复

- **对战页补上一级标题。** 原先整页没有 `h1`，读屏用户按标题跳转时没有落点。
  标题用 `sr-only` 放到正文开头——棋盘优先的布局不塞可见标题，但大纲完整。
  e2e 的标题用例原先名叫「四个页面」实际只查三个，现在真的是四个。
- **「减少动态效果」下连转圈也停了。** 系统开启该偏好后，「AI 思考中」那颗
  `animate-spin` 仍在无限转（WCAG 2.2.2 A）。现在它与其他四个动效一样被关掉，
  留下静态半环；未开启该偏好时照常转。
- **深色主题下手机地址栏跟着变深。** `meta[name=theme-color]` 原先固定浅色
  `#f6f4f0`，深色主题时浏览器 UI 仍是一条亮横条。现在 `applyTheme()` 同步为
  `#0f1115`。
- **刘海屏与手势条不再压住内容。** `viewport-fit=cover` 开了但从未使用
  `env(safe-area-inset-*)`。根容器补上四向安全区内边距（含顶栏）；无刘海设备上为 0。
- **AI 面板不再说「直接取胜」。** 那条 `reason: win` 既可能是「下一手成五」，
  也可能是算杀链的首手（本身不成五）。标签改为「算到必胜」，与下面那句
  「算出一条连成五子的必胜路线」同一个承诺强度。
- **`PHASE_05.md` 里一句与证据矛盾的「已交付」已更正**：F-UI-07/23/24 当时
  并未修。

### 验证

- 五条用户路径（对战 / 教学 / 残局 / 复盘 / 主题与恢复）在真实浏览器逐条走通。
- 探针重拍 38 个受控状态 / 308 张截图，与 Phase 00 的 19 个状态同口径对照。
- 六条门禁、四道防退化闸门、覆盖棘轮、基准全部实跑。

## Phase 06 · 棋谱复盘与 AI 分析（含交付后的两轮评审整改）

### 用户可观察

- **复盘页从「能看」到「能定位」**：时间轴可拖到任意一手；播放/暂停；
  三档速度；分析结论里的关键手可点击跳转并高亮。
- **分析面板标注出处与局限**：引擎版本、档位、预算常驻；「分差按棋型评分粗算，
  不是精确子数」；每一条结论标「搜索完成 / 预算内未搜完（启发式）」，
  且这个标签取一手所跨的**两次搜索中较差**的那个。
- **空状态与失败态说人话**：没下过棋时给「去下一局」的下一步；分析失败显示原因
  与「重新分析」；零手局不摆一颗点了没反应的按钮。
- **回放编号的字号达标**：`fontSize` 与半径解绑后，390 视口下 10.84px
  （`DESIGN_SYSTEM` §8.2 的下限是 10px）。
- **和棋、认输、终局的措辞各归各位**：「对局中 / 和棋 / 白方胜」按真实状态渲染。

### 工程

- `replayStore` 的定时器单一入口（`startTimer`），手动定位即暂停；卸载即停。
- 分析 `confidence` 取两次搜索较差者；`verdictLabel` 不再产出「分差约 0 子」。
- 复盘列表 → 回放的内部切换用 `key` 强制重建，换页焦点不再掉回 `<body>`。

## Phase 05 · 残局挑战

### 用户可观察

- **首页给出总进度、继续挑战入口与分类计数**；分类卡片带「x / y 完成」。
- **做完一题直接「下一题」**，反馈与提示不跟到下一题。
- **分类全部做完有完成提示**；做到最后一道给结束状态，不谎称全部通过。
- **判错标记不再是红圈里写「1」**：改成明确的符号。

### 工程

- 进度由 `PUZZLES × solvedPuzzles` 派生，没有新增重复状态；
  `PROGRESS_SCHEMA_VERSION` 与存储格式未动，存量进度无需迁移。

## Phase 04 · 互动教学

### 用户可观察

- **课程列表按阶段分组**，每课标完成状态；顶部给出已完成节数与推荐。
- **讲解页可上一步/下一步**，最后一页进练习；练习做错给理由，可重试；
  三级提示逐级具体，第三级才在棋盘上标点位。
- **做完一节课出现通过反馈与解法说明**，可「下一节」或回列表复习。
- **进度刷新后仍在**；载入前不断言「没做过」。

### 工程

- `learn/verify.ts` 的判定全部按目标谓词计算，不写死坐标；
  `content.test.ts` 逐题跑求解器。

## Phase 03 · 棋盘质感、标记与 AI 信息

### 用户可观察

- **最后一手高亮**：最近落下的一手与棋盘反色，看得见；胜利五子有连线。
- **落子编号与标记不再溢出底色**；两字标记的底色不比文字窄。
- **AI 面板分两级**：默认层说人话（「AI 在防守：你下一手能连成五子」），
  「?」展开才出现深度、节点、耗时等实现细节。
- **难度五档纵向排列**，不再挤成 3 + 2。

## Phase 02 · 对战主界面

### 用户可观察

- **1024–1439 宽的两栏布局**：棋盘从 362px 长到约 676px，右栏内容不再把棋盘压扁。
- **状态条迁到棋盘正上方**，「轮到谁」与棋盘在同一视线内。
- **会重建棋局的操作都要确认**：重新开始、切换模式、切换执子、认输；
  空棋盘重新开始不弹确认，点已选中的模式不弹。
- **确认弹窗可用键盘操作**，Escape 取消，焦点回到触发它的按钮。

### 工程

- 三档布局（单列 / 两栏 / 三栏）由同一组断点条件驱动，`wide-layout` 变体统一定义。

## Phase 01 · 视觉系统与页面外壳

### 用户可观察

- **四个页面共用一套颜色、字号、间距与圆角令牌**；深浅主题共用一份实现
  （组件里 `dark:` 前缀为 0）。
- **页面外壳统一**：顶栏在页面之间不跳，列表页滚动时导航不再跟着滚走。
- **棋盘不再塌陷**：教学 / 残局 / 复盘在 ≥1024 下从 169px 恢复到正常尺寸。

### 工程

- 28 个颜色令牌（浅深各一套）经 WCAG AA 反推；`contrast.test.tsx` 守着。
- `PageShell` 两个模式（阅读列 / 棋盘栅格），六个页面位置共用。
- 布局回归从「没有任何守护」变为 e2e 的尺寸预算断言。
