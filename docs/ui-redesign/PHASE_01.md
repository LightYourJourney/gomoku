为后续页面优化打地基。**不新增产品功能，不改动规则 / 引擎 / 持久化**。

| # | 范围 | 依据 | 对应发现 |

| 5 | 响应式复核（六档宽度 + 文字缩放） | 任务书 §七 | — |

## 二、设计令牌

### 2.1 颜色：一条都没改

现有 56 条 `--c-*` 声明（浅深各 28）是按 WCAG AA 反推出来的，156 次量测 0 处违规。
任务书说「基于现有语义令牌调整」「不要新建一套互相竞争的颜色体系」，
所以本阶段的动作是**把语义映射表写清楚**（`DESIGN_SYSTEM.md` §2.2），不换色。

「不使用颜色作为唯一的状态辨识方式」逐条查过：`good` / `bad` / `warn` 三处
都有伴随文字（「做得对。」「还不对。」「结论：启发式」）。
新加的顶栏选中态同时改**底色 + 文字色 + 阴影**三层，也不是只靠颜色。

**唯一写死的颜色**是品牌标记（见 §七之 3），理由与 `AppErrorBoundary` 相同：
自己画底就不能再继承——它不跟随主题是有意的。

### 2.2 字号：七级，只有两级需要自定义

| 级别 | 字号 / 行高 | 类名 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 20 / 28 | `text-xl` | 每页唯一的 `h1` |
| 浮层标题 | 18 / 26 | `text-lg` | `Modal` 标题 |
| 内容标题 | 16 / 24 | `text-base` | 面板内的大标题 |
| 区块标题 | 14 / 20 | `text-sm` + `text-muted` | `Panel` 的 `h2` |
| 强调正文 | 14 / 20 | `text-sm` | 按钮、值、状态条 |
| 正文 | 14 / 22 | `text-body` ← 自定义 | 段落 |
| 标签 / 辅助 / 数字 | 12 / 16 | `text-xs` | 字段标签、说明、徽标、坐标、计数 |
| 微字 | 11 / 16 | `text-micro` ← 自定义 | **全站仅一处**：品牌副标题 |

**只定义两级令牌**：其余六级的字号与行高和 Tailwind 默认值逐位相同
（`text-xl` 20/28、`text-lg` 18/28、`text-base` 16/24、`text-sm` 14/20、`text-xs` 12/16），
再起一套 `--text-page` 之类的别名只是把同一组数字写两遍。缺的恰好是这两级：
中文段落的行高要比 `text-sm` 的 1.25 宽，而 11px 在 Tailwind 里没有对应档位。

**18 处 `text-[11px]` 收敛到 12px**，只留品牌副标题一处。

### 2.3 间距：回到 4px 栅格

离栅格的 `p-3.5`(14) / `px-2.5`(10) / `p-2.5` / `py-2.5` / `px-3.5` / `gap-2.5` /
`gap-1.5` / `space-y-1.5` / `py-1.5` / `px-1.5` / `mt-1.5` / `mt-0.5` 全部吸附到
12 / 8 / 4。**2px 只允许三处**：徽标内部、紧邻文字的图标间距、密集数据表（棋谱）的行距。

**对右栏高度的净影响——算术与实测不一致，以实测为准：**

| 项 | 算术 | 说明 |
| --- | --- | --- |
| `Panel` 表头 | **0px** | 旧：`py-2.5`(20) + 行高 16 = 36；新：`py-2`(16) + 行高 20 = 36。表头高度 37px 不变 |
| `Panel` 内容 | −20px | 三块 14→12（各 −4）、棋谱 14→10（−8，见 §七之 2 的那个静默失效） |
| 字号 11→12 | +15px | `AI 引擎` 说明段 5 行 +8、`AI 提示` 脚注 4 行 +7 |
| **算术合计** | **−5px** | |

**实测（`ui:probe` 的 `scrollContainers`）：右栏藏起来的高度比基线多了 3px**
（`battle-midgame` 244 → 247、`battle-hint` 378 → 383、`battle-ai-error` 310 → 325）。

差出来的 8px 是若干处 +2/+4 的小改动累积：`gap-1.5→gap-2`、`ghost` 按钮从
「一行下划线文字」变成真实按钮（`min-h-6` + 内边距）、`Switch` 说明的 `mt-0.5→mt-1`。
**结论如实记下：本阶段没有让右栏更宽松，也没有明显更挤；F-UI-03 原样留给后续阶段。**
算术只给了上界，最后一句必须由实测说。

### 2.4 圆角、阴影、动效

- **圆角**：四档 + 全圆（内嵌 6 / 控件 8 / 容器 12 / 浮层与棋盘 16 + `rounded-full`）。
  唯一的例外 `rounded-[10px]`（品牌标记）随顶栏重构归并到 `rounded-xl`。
- **阴影**：一条变两条。`--shadow-panel`（面板）+ `--shadow-overlay`（浮层）。
  浮层与卡片共用同一条时，「这是个弹窗」这个信号就没了。
  **不加第三级**——次级表面靠底色区分。这一条改了 Phase 00 写的规范，已在文档里注明。
- **动效**：四个时长抽成 `--dur-banner/panel/stone/pulse`，缓动抽成 `--ease-entrance`。
  **值一个都没动**（就是原先写死的 `ease-out`）。**按用途命名而不是按大小排刻度**——
  全站一共四个动效，造一套 100/200/300 的刻度只会得到三个没人用的值。

## 三、组件

### `Button`

四个等级：`primary` / `secondary` / `ghost` / `danger`；两档尺寸：`md`（`min-h-9`）/ `sm`（`min-h-6`）。
`default` 保留为 `secondary` 的**别名**——**21 处调用点一处未改**（显式传 `variant` 的只有
`primary` 7 处与 `danger` 1 处，没有人传 `className`）。

补上 **`active`（按下）态**——此前四个等级一个都没有。
**不加 `loading`**：任务书写的是「仅需要时」，而当前没有调用方需要——「求提示」
「开始分析」的进行中状态由面板文案承担。加一个没人用的 prop 与 `AGENTS.md` 的
「不要提前构建用不到的能力」冲突。

**`ghost` 有三个真实调用方**（这是终审抓出来的一处「死能力」风险）：
`AiPanel` 的重试 / 知道了、`HintPanel` 的收起。它们此前是裸 `<button>`，
命中区只有 24×16 / 36×16，**低于 WCAG 2.5.8 的 24px 下限**，而这三处恰恰长在
「出错了要恢复」这条路径上。换成 `ghost` 之后命中区撑到 32×24 以上，外观几乎不变。

### `Panel`

- 标题 12 → **14px**（`text-sm font-semibold text-muted`）。它此前比面板**里面**的正文
  （14px）还小，容器的标签弱于内容，层级是反的。表头高度不变（见 §2.3）。
- **内边距改由 `padding` 档位控制**（`normal` / `tight` / `roomy`），不再走 `bodyClassName`。
  这是一处**真实缺陷的修复**，见 §七之 2。
- 残局列表的分类面板里，每道题**不再各带一条边框**（原来是「边框套边框」）。
- 教学列表底部的「学完之后」整块 `Panel`（只有一个句子）**降级为普通段落**。

### `Segmented`

`role="radiogroup"` 的**键盘行为补全**：整组只有一个 Tab 停靠点（roving tabindex），
方向键移动并真的 `focus()`，`Home` / `End` 跳两端，到端即停不绕回，禁用项跳过。
此前每个选项各自是一个 Tab 停靠点、方向键完全没反应——对读屏用户来说，
听到「单选按钮 1 / 3」之后按方向键什么都不会发生。

选项加 `min-w-0 truncate`，完整文案走 `title` 兜底（窄栏里标签会被截断）。

### `Switch`

**可访问名与说明拆开**：说明走 `aria-describedby`，名字走 `aria-labelledby`
（不是 `aria-label`——名字仍然来自屏幕上真实存在的文字，改了文案不会出现「看得见的字
与念出来的名字对不上」）。此前名字由内容顺带带出，实际是
「显示坐标棋盘四周标注 A–O / 1–15」——每听一个开关都要把说明念完才知道是哪一个。

**只加 `aria-describedby` 是不够的**：名字来自内容，说明仍然在名字里，结果是念两遍。
这一条是终审用一个十行的脚本实测出来的（`dom-accessibility-api` 三种写法各自的
name/description），计划书当时写错了。

### `Modal`

- 标题 16 → 18px；浮层阴影；正文用 `text-body`。
- **按钮顺序统一为「次要操作在左、主操作在右」**，用 **DOM 顺序**表达，
  不用 `flex-row-reverse`——反排会让 Tab 顺序与视觉顺序相反，键盘用户从右往左跳。
- `aria-modal` / 焦点陷阱 / `Escape` / 关闭后焦点处理**一行未动**。

### `AppHeader`

```
桌面：[品牌 36×36 + 名称/副标题]  [导航]  ······  [状态条] [主题]
窄屏：[品牌]  ······  [状态条] [主题]
      [导航 —— 等宽四列，铺满整行]
```

- 品牌标记改成**内联 SVG**（原因见 §七之 3）；底板 32 → 36px、`rounded-xl`。
- 导航项 12 → 14px、`min-h-8`（24 → 32px 命中高度）、`px-3`；选中项用
  `bg-accent-soft text-accent`。
  **不用「浮起的白底」**：令牌层级在深色里是 `surface`(深) → `surface-2`(浅)，
  同一套类名在浅色下是浮起、到深色就成了凹陷——这是拍完 after 截图目视复核时发现的，
  改完重拍了一次。
- 窄屏导航等宽四列铺满整行（原来左对齐、右侧空约 180px）。
- 主题按钮 32 → 36px。
- `min-h-15`（60px）：**高度不随页面跳**（实测三个页面之间差 <1px）。
- `sticky top-0`。

### 页面容器壳（新增 `src/features/shell/PageShell.tsx` + `components/ui/PageHeader.tsx`）

| 模式 | 正文 | 谁在滚 | 用在 |
| --- | --- | --- | --- |
| `reading` | 居中限宽列 `max-w-3xl` | `<main>`（顶栏在它**外面**） | 教学 / 残局 / 复盘的列表页 |
| `flush` | 自己管栅格（`lg` 起两栏：棋盘 + 344px 侧栏） | 页面自己 | 课程讲解、练习、残局详情、复盘回放 |

**为什么顶栏必须在滚动容器外面，而不是靠 `sticky` 兜底**：sticky 相对「最近的可滚动
祖先」定位，而列表页在 ≥1024 时滚的是内层 `main`、<1024 时滚的是文档。
把顶栏放进滚动容器，这两种宽度下它的行为就不一样了——正是 F-UI-21 的成因。
放进外壳、与正文平级之后，两种宽度都不用 sticky 也永远在（实测两个宽度都验过）。

**`PageShell` 住在 `features/shell/` 而不是 `components/ui/`**：它要渲染 `AppHeader`，
而 `AppHeader` 读 store；放进 `components/` 就成了 `components → features`，
与「依赖方向单向」相反。

**对战页不用它**——任务书 §六 明确说棋盘优先布局与阅读布局不该统一宽度。

## 五、自审记录

### 第 1 轮

1. **任务书的 Phase 01 与 `PLAN.md` 的 Phase 01 不是同一件事。** 照 `PLAN.md` 执行会把
   「侧栏 clamp」做进来——任务书把它留给 Phase 02。→ 在 §〇 写清两条判断。
2. **F-UI-01 做不做，原计划没回答。** → 决定做，理由写在 §〇。
3. **字号升级会把右栏溢出推高。** → 先算净影响，再用 `ui:probe` 复核。
   **事后证明这条是这一轮最值钱的一条**：算术给的是 −5px，实测是 +3px。
4. **`Button` 加 `ghost` 会不会破坏调用方？** → `grep` 全部 21 处调用点确认。

### 第 2 轮

5. **`Modal` 按钮顺序改了会动到测试。** → 读了 `ResultDialog.test.tsx`（4 条，全断言存档文案，
   无顺序断言）、`Modal.test.tsx`（自带 Harness）、`e2e/a11y.spec.ts`（只断言 Tab 出不去与
   Escape 后的焦点文本）。**悬念有答案了：不用改。**
6. **`Segmented` 加方向键要动 `role` 语义**，方向键一旦有 bug，键盘用户会彻底进不去。
   → 四条键盘用例 + 一条真实浏览器 e2e。
7. **顶栏改 `sticky` 有风险**：对战页根是 `h-dvh overflow-hidden`，列表页 ≥lg 滚内层 div。
   → **这条我判断错了一半**，见 §六之 R-02：真正的解法不是 sticky，是把顶栏放到滚动容器外面。
8. **`PageShell` 会不会变成「通用 UI 框架」？** → 限定两个模式、三个可选插槽。

### 第 3 轮

9. **徽标里的 11px 升到 12px 会不会装不下？** → 那些徽标是 `h-5 w-5` / `h-6 w-6` 的单字符，
   12px 放得下；**仍逐张截图确认**。
10. **`min-h-15` 的顶栏在 390 下会变两行**，`min-h` 只管下限不管上限。
    → e2e 补了「高度跨页面不跳」与「窄屏导航铺满」两条。
11. **`PageHeader` 的 `h1` 会不会与 F-UI-11 冲突？** → 统一了三个列表页的 `h1`（它们本来就有），
    对战页与详情页的 `h1` 留给 Phase 06，避免两阶段改同一批文件。
12. **阴影加第二级与 `DESIGN_SYSTEM` §5.2「只有一个阴影」矛盾。** → 改文档，并在文档里
    留一句「Phase 00 时写的是一个，Phase 01 补了第二级」。
13. **探针的 `before/` 与本阶段的截图会有大量预期差异。** → 对照分三类看。

## 六、独立终审

由另一个上下文执行（读代码、复算数字、逐条对照仓库约定），**21 条里 20 条属实，全部已改**。
完整结论在它自己的报告里，这里只记**三条硬伤**与我当时的判断错在哪：

| # | 终审指出 | 我的判断错在哪 | 处置 |
| --- | --- | --- | --- |
| **R-01** | 统一门槛里有一条**永远红的判据**：要求棋盘命中区 ≥24px，而一格 = 棋盘/16，390 屏幕满幅也只有约 24px，且规范明令不许放大命中区 | 我把它当成了「严格一点更好」 | 判据改成「`under24` 只允许剩下棋盘交叉点」。**一条永远红的判据会被当成噪声——那正是 P0 得以存活的同一种失效模式** |
| **R-02** | `sticky` 在 <1024 不生效：列表页在窄屏是**文档**在滚，而顶栏在 `overflow-y-auto` 的 div 里 | 我只考虑了「两种滚动容器」，没想到「内层容器根本不滚」这一种 | 真正的解法是把顶栏放到滚动容器**外面**（`PageShell` 已经这么做了），sticky 只是兜底。e2e 在 390 与 1440 两个宽度都断言了 |
| **R-03** | 棋盘换算基准写错了：`viewBox` 是 `1 + 14 + 1 = 16` 个单位，不是 17 | 我按 17 折算了一整份文档，**而探针量的 `intersection-7-7` 早就在数据里**，四次全部等于「棋盘/16」 | 全部重算（坐标标签 0.52 单位 → 390 下 11.05px；回放编号 0.325 → 6.91/8.31px） |

其余是三类：**判据本身是空断言**（`buttons` 里查段落文字、探针没有 `headings` 宽度字段、
把难度控件判在 `puzzle-list` 上）；**清单漏了要改的文件**（`ReviewScreen`、`bench/ui.probe.mjs`）；
**与仓库既成约定冲突**（用 `matchMedia` 判指针类型 —— 改成用事件自带的 `event.pointerType`，
这条改完比原方案更好）。

它同时确认了一件事：**这四项改动不会让任何既有测试变红**（逐条核过 12 个测试文件），
唯一会红的是我自己刚写下的 TDD 用例。事后实测印证了这一点。

### 2. 顺带查实的两处缺陷

**`Panel` 的 `bodyClassName` 内边距覆盖静默失效。**
`Panel` 渲染 `cx('p-3.5', bodyClassName)`，而 Tailwind 的同名工具类**没有优先级**——
谁在生成的 CSS 里靠后谁赢。构建产物里的字节偏移是 `.p-2.5`(15051) < `.p-3`(15094) <
`.p-3\.5`(15132)，所以 `bodyClassName="p-2.5"` 会被面板自带的 `p-3.5` 盖掉，
而 `p-8` 恰好排在后面所以生效——**同一个 API 一处生效一处不生效**。
量面板内边距时发现「棋谱」的 `bodyPadding` 是 `14px`（想要 10px），回去翻构建产物确认。
现在内边距有独立入口 `padding`，六处冗余的 `p-3.5` 一并清掉。

**品牌标记的五颗子溢出底板。**
32px 的底板（`x=24..56`）里塞了 47px 宽的一排圆点，一直排到 `x=71`——
第 4、5 颗压在「Gomoku Lab」上面。改成内联 SVG，尺寸只有一个来源，不可能再画出去。
改完放大截图复核时又发现**暗色下整个标记几乎看不见**（木纹令牌在暗色是近黑的 `#3b3129`，
黑子 `#0b0b0d` 压上去直接消失），于是把品牌配色写死、不跟随主题——
它不是界面的一部分，是标识。

### 3. 三处「写完规范就地修掉」的违反

本阶段给自己定了三条新规则，复核截图时发现自己的代码各违反一处，当场修掉——
**定一条规则却留着自己的代码违反它，那条规则从第一天起就是装饰**：

| 规则 | 违反处 | 修法 |
| --- | --- | --- |
| 一屏最多一个 `primary`（§6.1） | `review-replay` 的「← 回到棋谱列表」与「开始分析」同为实心强调色 | 前者是导航，降为 `secondary` |
| 顶栏选中态深浅一致（§10.3） | 「浮起的白底」在深色下变成凹陷 | 改 `bg-accent-soft text-accent` |
| 品牌是标识、不随主题变（§2.1 的例外） | 暗色下木纹令牌近黑，黑子直接消失 | 品牌配色写死 |

前两处是**拍完 after 截图目视复核**发现的，第三处是放大 6× 截品牌时发现的。

### 4. 一处判断的更正

`Modal` 的按钮顺序**改了**：主操作从左边挪到右边。理由是与 `Button` 的等级一起看时，
「最右边的那个是主操作」是一条能一眼学会的规则；而此前
「再来一局」在左、且是唯一的实心按钮，与其它地方「实心在右」的习惯不一致。
