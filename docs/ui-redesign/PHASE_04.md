## 三、要改的东西

### 3.1 分阶段（任务书 §二）

**展示层分组，不碰内容层。** 新增 `src/features/learn/courseOutline.ts`：一张
「阶段 → 课程 id」的表，四组：

| 阶段 | 课程 |
| --- | --- |
| 基础入门 | `rules`、`two` |
| 棋型进阶 | `three`、`four` |
| 攻防策略 | `double`、`defense` |
| 综合实战 | `combo`、`vcf` |

**分组表要有守卫**：一条单测断言「八节课**恰好**各出现一次、表里没有不存在的 id」——
否则以后加第 9 节课，它会静默地从列表里消失（这类「新东西悄悄不在扫描里」本仓中过一次，
见 `PHASE_02` 的三颗控件）。

**同一个模块里再放两个纯函数**（都在展示层，都可直接单测）：

```ts
stageOf(lessonId): Stage | null          // 这节课属于哪一组（列表渲染用）
resolveNext(lessons, progress):           // 「继续学习」指向谁
  | { kind: 'lesson'; id: string }        //   优先：上次停留且**未完成**的那节
  | { kind: 'allDone' }                   //   八节全完成
  | { kind: 'lesson'; id: string }        //   否则：第一节未完成的
```

**为什么不把分组写进 `learn/lessons.ts`**：那是内容层，`content.test.ts` 在守它；
而分组是**展示决策**（任务书 §二 也写的是「展示层分组」）。放进去就等于让内容层替界面表态。

### 3.2 进度与推荐（任务书 §三）

- **进度条** + 「已完成 X / 8」，数据全部来自 `progress.completedLessons` 与 `LESSONS` 的交集，**不硬编码**。
- **推荐继续**：优先 `lastVisited`（若它是一节**未完成**的课）；否则第一节未完成的课；
  全完成时给「八节都完成了」的状态条（任务书 §三 末条 + §九 末条）。
- **加载态**：`loaded === false` 时显示骨架/占位，**不显示「已完成 0 节」**（现行为已对，保持并补测试）。
- **顺带修一处硬编码**：`LearnScreen.tsx:78` 的介绍文案写死「**八节课**从规则讲到做杀…」。
  计数那句（`:75`）是 `LESSONS.length` 推出来的 ✔，介绍这句不是 ✗——加第 9 节课时它会撒谎。
  改成由 `LESSONS.length` 生成（或去掉数字），并加一条用例钉住。

### 3.3 卡片（任务书 §四）

- 保留：章节序号、名称、简介、状态、整卡可点（`<button>` ✔ 键盘可达）。
- **补 `active:` 反馈**（任务书 §四 的「明确点击反馈」）：卡片现在只有 `transition` 与
  `hover:`（`LearnScreen.tsx:92-97`），**按下时没有任何变化** ✗。
- **改已完成态**：现在是整片 `bg-good-soft`（`:95`）。换成低权重标识——**令牌指名**：
  底色回到 `bg-surface`（`surface-2` 按 `DESIGN_SYSTEM.md` §2.1 不用于大面积背景），
  用**勾 + `text-good` 的字**表达完成，不铺色。
- **推荐那一张**加权重，但**与顶部的推荐入口合成一件事**（见下）。
- **列表页通往残局的入口**（任务书 §二⑥）：把那句纯文字（`:129-132`）升级成可点的入口，
  放在列表**末尾**、与「下一步」语义一致的位置；它指向 `puzzles` 视图（`setView('puzzles')`，
  与顶栏导航同一条路），**不是**新开一层。

### 3.3.1 一处设计冲突要先解掉：同屏两个「推荐」

初稿让**顶部推荐入口**（§3.2）和**卡片高亮**（本节）同时指向同一节课，两处都用 `accent` ✗。
`DESIGN_SYSTEM.md:72` 写着「`accent` 不是「强调」的同义词…用错地方会让重点失效」，
而 §6.1 的「一屏最多一个 `primary`」只管按钮数量、管不住这种重复。

**解法（按「谁才是那个动作」分）**：

| 位置 | 做什么 | 用什么令牌 |
| --- | --- | --- |
| 顶部进度区 | **唯一的主操作**：「继续学习：<课程名>」（按钮，点了直接进那节课） | `primary`（`accent`） |
| 推荐那张卡片 | 只做**弱标记**：左边一条竖条 + 「接下来」小字，**不重复放按钮** | `border-strong` + `text-muted` |

理由：一屏只留一个 accent 动作；卡片仍然「增强了视觉权重」（任务书 §四 允许），
但不用颜色和第二颗按钮去抢它。**导航上也不该有两个控件通向同一个地方**——
那对读屏用户是两个「继续学习」，反而更绕。

### 3.4 步骤导航（任务书 §六，**本阶段的核心改动**）

`LessonView` 的步骤模型现在是 `step: number`，练习是「最后一页之后」。
改成显式的两态：`讲解 step ∈ [0, steps.length)` 与 `练习`，并补：

- **「上一步」**：第 0 步**禁用**（任务书 §六 允许「正确禁用或隐藏」，选禁用）——
  **渲染但不可点**，理由是消失会让工具栏左右跳动，而「不能后退」用禁用表达得更准确。
- **「回到讲解」**：在练习态渲染，回到**最后一页讲解**（`steps.length - 1`）。
  **它绝不能调 `completeLesson`** —— 这条要有专门的用例（返回讲解后 `isLessonDone` 仍为 false）。
- **最后一步的主按钮改文案**：现在是「下一步」，点下去直接跳到练习——**动作发生了但没人说**
  ✗。改成「**进入练习 →**」（任务书 §六 点名的「进入练习」）✔。
- 步骤计数继续用 `N / M`（讲解步数），练习态显示「练习」✔ 现状如此。
- **`onNext` 的现状要说准**：footer 是 `{solved && footer}`（`PracticeBoard.tsx:188`），
  也就是**只有判对之后才出现「下一节 →」**——初稿写成「不因未通关而禁用」，与代码相反 ✗。
  这条**保持现状**（任务书 §六 要的正是「练习完成后下一课」），
  任务书 §四 的「不强制按顺序解锁」讲的是**列表选课**，不是这个按钮。

### 3.5 完成体验（任务书 §九）

- 通过时：`FeedbackBanner`（已有）+ 明确肯定语（§八）。
- **最后一课通关后**：底部按钮从「下一节 →」换成**通向残局挑战**的入口。
  实现方式：把「接下来去哪」表达成**一个**出口描述符（`{ kind: 'next', run } | { kind: 'puzzles', run }`），
  而不是并列两个可选回调——两个 `onX?: () => void` 同时可传，就默认了「哪个优先」这件
  没写下来的隐式状态。`LearnScreen` 已经知道 `index === LESSONS.length - 1`，由它决定传哪个 ✔。
- **八节全完成**：列表页顶部给一条完成状态（不是弹窗、不给分数等级——任务书 §九 明说不许）。

### 3.6 练习界面（任务书 §八）

- 反馈条显式标注**判定来源**：这句话来自 `judgeMove` 的真实判定，不是预置台词。
- 做对后的肯定与「完成后继续学习」的路径（footer 已有，措辞收紧）。
- **不动**：`judgeMove`、`solveMove`、三级提示的揭示顺序、判错锁盘。

### 3.7 棋盘讲解（任务书 §七）

- 字与盘的距离：`StepView` 的讲解面板已在棋盘右侧/下方（`order-2 lg:order-3`）✔，
  收紧标题与正文的层级，让「当前知识点」一句话就能读到。
- **不加新标记**：「一屏聚焦一个核心概念」意味着**不要再堆提示**。
  现有 `marks` + 手顺演示已经够用，本阶段只保证它们和文字对得上。

### 3.8 无障碍与响应式（任务书 §十.12）

- 阶段标题用 `<h2>`（现在列表是裸 `<ol>`，加分组后必须给每组一个标题层级，
  否则读屏用户听到的是「八个并列按钮」，不知道分了组）。
- 进度条要有 `role="progressbar"` + `aria-valuenow/max`，否则它只是一条彩带。
- 新增的「上一步 / 回到讲解」是原生 `button` ✔（Tab 可达）。
