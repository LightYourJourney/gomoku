# UI 设计规范（Phase 00 定稿）

这份规范写给**实现它的人**：每一条都能落到一个类名、一个令牌或一条判据上，
没有「更优雅」「更有呼吸感」这类无法验收的说法。

它是从**当前真实的界面**里长出来的（基线见 [BASELINE.md](BASELINE.md)，
问题清单见 [FINDINGS.md](FINDINGS.md)），不是另起一套设计稿。
**已经达标的东西一个都不推翻**——§0 先把它们列清楚。

---

## 0. 先确认：哪些已经是对的，不要动

改版最大的风险不是「改得不够」，是**把已经达标的东西改坏**。
下面这些在 156 次真实量测里全部通过，改版期间必须保持：

| 资产 | 现状 | 守卫 |
| --- | --- | --- |
| **对比度** | 19 个状态 × 8 档视口主题 + 4 张矮窗口补拍 = **156 次量测**逐元素扫过，**0 处低于 AA 4.5:1** | `src/lib/contrast.test.tsx` 两层守卫（令牌层 21 组配对 + 用法层逐元素扫真实页面） |
| **两套主题共用一份实现** | 组件里**零个** `dark:` 前缀，主题只改 `<html>` 上的一个类 | `index.css` 的 `@theme inline` |
| **棋盘键盘可达** | `role="grid"` + roving tabindex（单一 Tab 停靠点）+ 方向键 / Home / End / Enter | `Board.test.tsx`、`e2e/a11y.spec.ts` |
| **播报只有一处** | `BoardAnnouncer` 是唯一的 live region；药丸刻意**不是** | `BoardAnnouncer.test.tsx` |
| **棋盘焦点环** | 自绘双色环（主色 + 反色晕），四种底色下至少一个过 3:1 | `lib/contrast.test.tsx` 的棋盘一组 |
| **命中区无缝** | 按格铺满的正方形 + `strokeWidth 0`，不存在格间死区 | `e2e/tablet.spec.ts` 的四角与四边中点 |
| **棋盘自适应** | CSS 容器查询，`min(100cqw, 100cqh)`，无 JS 测量 | `BoardStage.tsx` |
| **动效降级** | 四个 `@keyframes` 走纯 CSS，`prefers-reduced-motion` 关掉 | `index.css`（**但见 §9 的例外**） |
| **错误态可恢复** | AI 报错有「重试」入口且不随错误消息一起消失；存档失败如实说 | `AiPanel.tsx` 的注释、`ResultDialog.tsx` |

> 改动本节任何一项，都必须在 `FINDINGS.md` 里留下「为什么要动它」的记录。

## 1. 产品定位与设计原则

**现代极简五子棋游戏 + 温润棋盘 + 专业 AI 分析实验室。**

七条原则，后面每一节都是它们的展开：

1. **棋盘优先。** 任何宽度下，棋盘都是屏幕上最大的可交互资产。侧栏、说明、次要按钮先让位——**先缩面板，再缩棋盘**。
2. **温润，不炫技。** 浅色干爽、深色沉稳。不做纯黑高对比、不做玻璃拟态、不做夸张渐变、不做持续动画。
3. **一屏一个重点。** 同一视口内，实心主色按钮**最多一个**（弹窗打开时不算同屏）。
4. **技术信息渐进披露。** 默认界面只给结论与可操作项；术语、算法、参数收进可展开处。
5. **中文优先的排版。** 正文不小于 14px，标签与辅助文字不小于 12px，**阅读性文字不用 11px**。
6. **少即是多。** 减少细小文字、减少重复边框、减少并排的同等权重按钮。
7. **动效只标注变化，不装饰。** 只在「真的发生了什么」的那一刻播。

## 2. 颜色

### 2.1 令牌：一个都不改

`src/index.css` 里有 **56 个 `--c-*` 声明：`:root` 28 个、`.dark` 28 个，名字一一对应**
（`grep -c "^\s*--c-" src/index.css` = 56）。它们是**按 WCAG AA 反推出来的**，
并且有 156 次真实量测佐证全部达标。**本规范不改任何一个值。**

要改，先跑 `yarn test src/lib/contrast.test.tsx`，并在 `FINDINGS.md` 里说明改的理由。

### 2.2 语义映射（写组件时按这张表选，不要按颜色名字选）

| 令牌 | 用在哪 | 不要用在 |
| --- | --- | --- |
| `bg` | 页面底色、`<body>` | 卡片 |
| `surface` | 面板、卡片、弹窗、棋盘容器 | 页面底 |
| `surface-2` | 面板内的次级块（分段控件的槽、统计格、表格斑马行）、悬停底色 | 大面积背景 |
| `border` | 面板与控件的默认描边 | 强调 |
| `border-strong` | 控件的 hover 描边、开关的关闭态 | 常态 |
| `fg` | 正文、值、强调文字 | 说明文字 |
| `muted` | 次要说明、面板标题、导航未选中 | 正文 |
| `faint` | 三级信息（时间、坐标说明、脚注） | 正文与按钮 |
| `accent` / `accent-soft` / `accent-fg` | 主操作、当前选中项、提示标记、胜利连线 | 装饰性高亮 |
| `danger` / `danger-soft` | 认输、错误、判错反馈、最后一手环 | 一般警示 |
| `good` / `good-soft` | 做对、已完成、成功 | 主操作 |
| `warn` / `warn-soft` | 危险提示、启发式结论、防守标记 | 错误 |

**`accent` 不是「强调」的同义词**，它是「主要操作」与「当前所在位置」。用错地方会让重点失效。

### 2.3 对比度要求

- 正文与控件文字：**≥ 4.5:1**（AA）
- 大字（≥24px 或 ≥18.66px 且 700）：≥ 3:1
- 非文字（图标、边框、焦点环、棋盘线条）：≥ 3:1（AA 1.4.11）
- **棋盘上的元素另算**：木纹是渐变的，通用对比度工具量不了，所以焦点环、网格线、星位、棋子描边四项各自在 `lib/contrast.test.tsx` 里单独守着。

## 3. 字体与排版

### 3.1 字族

```
--font-sans: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Noto Sans SC', sans-serif
--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace
```

**等宽只用于数字与坐标**（棋谱、计数、评分、深度、节点、耗时）。正文用等宽是本仓库不允许的。

### 3.2 字号等级（**唯一出处**）

现状实测是五种字号散落在各处（11 / 12 / 14 / 16 / 18），其中 12px 单页最多**渲染** 87 次；
11px 在**源码里出现 18 处** `text-[11px]`，**单页最多渲染 17 处**。
**收敛成下面六级，不再新增字号。**

| 级别 | 字号 / 行高 | 字重 | 类名 | 用途 |
| --- | --- | --- | --- | --- |
| 页面标题 | 20 / 28 | 600 | `text-xl` | 每个页面**有且只有一个** `h1` |
| 浮层标题 | 18 / 26 | 600 | `text-lg` | `Modal` 标题 |
| 内容标题 | 16 / 24 | 600 | `text-base` | 面板内的大标题（讲解页的步骤标题、终局结论） |
| 区块标题 | 14 / 20 | 600 | `text-sm` + `text-muted` | `Panel` 的 `h2` |
| 强调正文 | 14 / 20 | 500 | `text-sm` | 按钮、值、状态条、开关标签 |
| 正文 | 14 / 22 | 400 | `text-body` | 段落（讲解正文、题目、说明） |
| 标签 / 辅助 / 数字 | 12 / 16 | 400–700 | `text-xs`（数字另加 `font-mono tabular-nums`） | 字段标签、辅助说明、徽标、坐标、计数、评分 |
| 微字 | 11 / 16 | 400 | `text-micro` | **全站只允许一处**：品牌副标题「五子棋实验室」 |

**只有两级需要自定义令牌**（`--text-body` / `--text-micro`，定义在 `src/index.css`）：
其余六级的字号与行高和 Tailwind 默认值逐位相同（`text-xl` 20/28、`text-lg` 18/28、
`text-base` 16/24、`text-sm` 14/20、`text-xs` 12/16），再起一套 `--text-page` 之类的
别名只是把同一组数字写两遍。缺的恰好是这两级：中文段落的行高要比 `text-sm` 的 1.25 宽，
而 11px 在 Tailwind 里没有对应档位。

**区块标题用 14px 而不是更小**：它要是比面板**里面**的正文（14px）还小，
容器的标签就弱于内容，层级是反的。现在两者同号，靠字重（600 vs 400）与颜色
（`text-muted` vs `text-fg`）区分。

**禁止 11px 出现在阅读性文本上。** 唯一的例外是品牌副标题——它是标识的一部分，
不是要读的句子。

### 3.3 行高与行宽

- 中文段落的行高**不低于字号的 1.5 倍**（14px → 21px 以上；现值 22.75px ✓）。
- 单行中文长度控制在 **28–45 字**。超过就分段或收窄容器。
- 长文本容器加最大宽度（现有 `max-w-3xl` = 768px 是合适的，继续用）。

## 4. 间距

**基准 4px。** 只允许这几个值：

| 值 | Tailwind | 典型用途 |
| --- | --- | --- |
| 4 | `gap-1` `p-1` | 图标与紧邻文字、分段控件的槽 |
| 8 | `gap-2` `p-2` | 同组控件之间 |
| 12 | `gap-3` `p-3` | 面板内元素间距 |
| 16 | `gap-4` `p-4` | 面板内边距、栅格间距 |
| 24 | `gap-6` `p-6` | 区块之间、页面左右留白 |
| 32 | `gap-8` `p-8` | 页面上下留白（大屏） |

**明确禁止**：`p-3.5`(14) `px-2.5`(10) `gap-2.5`(10) `py-1.5`(6) `gap-1.5`(6) `py-0.5`(2)。
它们现在散落在 20 多处，是把 4px 栅格磨成「差一点点」的主要来源。
唯一豁免：`py-0.5`/`gap-0.5` 这类 **2px** 只允许出现在徽标内部。

## 5. 圆角与阴影

### 5.1 圆角：四种 + 全圆

| 档 | 值 | 类名 | 用在哪 |
| --- | --- | --- | --- |
| 内嵌 | 6 | `rounded-md` | 分段控件里的选项、列表里的徽标 |
| 控件 | 8 | `rounded-lg` | 按钮、开关槽、输入、导航项 |
| 容器 | 12 | `rounded-xl` | 面板、卡片、列表条目 |
| 浮层 | 16 | `rounded-2xl` | 弹窗、棋盘外框 |

外加 `rounded-full`（药丸、圆点、开关的滑块）。

现状六种（6/8/10/12/16/full）里的 `rounded-[10px]`（品牌标记）归并到 12。

### 5.2 阴影：两级

| 令牌 | 用在哪 |
| --- | --- |
| `--shadow-panel` | 面板、卡片 |
| `--shadow-overlay` | 浮层（`Modal`）——它压在整页之上，需要把下面的内容推开 |

**只有这两级，不再加第三级。** 次级表面（`surface-2` 上的块）靠底色区分，不加阴影。

> Phase 00 时这里写的是「只有一个阴影」。Phase 01 按任务书 §三 的「阴影层级」
> 补了第二级并改了这条——浮层与卡片用同一条阴影时，「这是个弹窗」这个信号就没了。

## 6. 按钮与状态

### 6.1 四个等级

| 等级 | 视觉 | 用途 | 一屏数量 |
| --- | --- | --- | --- |
| `primary` | `bg-accent text-accent-fg` 无边框 | 当前唯一的下一步（求提示、下一节、再来一局、开始分析） | **≤ 1** |
| `secondary` | `bg-surface-2` + `border-border` | 常规操作（悔棋、重新开始、上一步、看看棋盘） | 不限 |
| `ghost` | 透明 + `text-muted underline` → hover `bg-surface-2 text-fg` | 轻量内联操作（重试、知道了、收起） | 不限 |
| `danger` | `bg-danger-soft text-danger` | 破坏性操作（认输） | ≤ 1 |

`default` 保留为 `secondary` 的**别名**——它曾经是唯一的默认档，
现有调用方里还有人显式写着 `variant="default"`。改名不该让调用方跟着改。

**「一屏最多一个 `primary`」是 Phase 01 新增的规则，同阶段就修掉了它唯一的一处违反**：
`review-replay` 里 `回放` 面板的「← 回到棋谱列表」原先是 `primary`，
与 `引擎分析` 面板的「开始分析」同屏（该状态下右栏高 459 px，不滚动）。
「回到棋谱列表」是**导航**不是本页的主操作，已降为 `secondary`——
两个实心强调色按钮并排时，用户不知道该按哪个。

**`ghost` 是新增的第四档**，用来收编原先散落的裸 `<button>`
（`AiPanel` 的重试 / 知道了、`HintPanel` 的收起）。它们此前**连 24×24 的命中区都没有**
（实测 `收起` 与 `重试` 是 24×16、`知道了` 是 36×16，低于 WCAG 2.5.8 的 24px 下限），
而这三处恰好长在「出错了要恢复」这条路径上。`ghost` 档自带内边距，
命中区撑到 32×24 以上，外观几乎不变。

**尺寸两档**：`md`（`min-h-9`，36px）与 `sm`（`min-h-6`，24px，给 `ghost` 用）。
两者都是 `min-h-*` 而不是固定高度——文案换行或放大字号时按钮跟着长高，而不是把内容裁掉。

### 6.2 状态

| 状态 | 规则 |
| --- | --- |
| hover | 控件：`border-border-strong` 或 `brightness-110`；文本：`text-muted → text-fg` |
| active | 按下必须有反馈：实心档用 `active:brightness-95`，描边档用 `active:brightness-95`。四个等级都带上了（Phase 00 时这一态完全不存在）。 |
| disabled | `disabled:opacity-40 disabled:cursor-not-allowed`（保留） |
| focus-visible | 全局 `outline: 2px solid var(--c-accent); outline-offset: 2px`（保留）；棋盘自绘环 |
| 加载中 | 按钮文字不变，**禁用 + 文案明确**（现有「正在计算提示…」这类文本提示是对的，不要改成纯转圈） |
| 错误 | 必须带**下一步动作**（现有的「重试」就是对的），且错误消息不能与动作一起消失 |

**状态不能只靠颜色区分。** 对/错、警告/一般都必须同时有文字或图形差异（现状做到了，继续保持）。

## 7. 渐进披露

这是本规范里**唯一一条新增的交互模式**，用来解决最扎眼的一处信息过载。

- 默认界面上**不允许出现**：算法名称（Negamax / Alpha-Beta / Zobrist / VCF / VCT）、
  实现细节（Web Worker、置换表、杀手着法）、内部参数（预算毫秒数、候选宽度）。
- 这些内容收进：面板标题右侧的一个「?」按钮 → 展开为浮层或内联块；或折叠区（`<details>`）。
- 展开状态**不持久化**（每次进来都是收起的）。
- 判据：**1440×900 下，对战页右栏四块面板的总高度不得超过侧栏可视高度**（现在超了，
  见 FINDINGS 的 F-UI-03）。

**一处显式豁免：复盘分析的出处行。**
`ReviewScreen` 的「初级 · 400ms · 引擎 search-1」按本节本该收起来（它含档位与预算毫秒数），
但 `AGENTS.md` 明确要求「分析结论必须注明引擎、**预算**与局限」——
`400ms` 是结论能不能被解读的前提，不是可以藏起来的技术细节。
**豁免的边界**：留在明面的只有「档位 · 预算 · 引擎版本」这一行；
`搜索深度` / `节点` / `可靠度` 那些逐条结论里的数字，随结论一起展示，也不进折叠区。
**该收的是「为什么用 Negamax」这类实现说明，不是「这份结论是怎么算出来的」。**

## 8. 棋盘

棋盘是本产品的主要视觉资产，规则也最硬。

### 8.1 尺寸

```
容器：container-type: size  —— 且必须有确定高度
棋盘：aspect-ratio: 1；width: min(100cqw, 100cqh)
```

**硬约束：不要把棋盘放进高度为 `auto` 的网格行或弹性行。**
`container-type: size` 会触发尺寸包含（size containment），容器高度由内容决定时
`100cqh` 会退化——这正是 F-UI-01 那起事故的机制（棋盘塌到 169px）。

**最小可用尺寸：320 CSS px 见方。** 按「1 单位 = 棋盘/16」算，那时一格 **20 px**、
交叉点命中区 20×20。任何布局都不得把棋盘压到这个值以下；
达不到就让侧栏让位（折叠、换行、降级为抽屉）。

### 8.2 棋盘上的文字

按**实际像素**定下限，不按 SVG 用户单位：

**换算基准写死在这里，别各算各的**：`Board.tsx` 的 `viewBox` 是
`MARGIN 1 + EXTENT 14 + MARGIN 1 = 16` 个用户单位，
所以 **1 用户单位 = 棋盘宽 / 16**。探针量的 `intersection-7-7`（正好一格）四次全部吻合：
340/16 = 21.25、478/16 = 29.88、362/16 = 22.63、778/16 = 48.63。

| 元素 | 用户单位 | 折算字号 | 判据 |
| --- | --- | --- | --- |
| 坐标标签 | 0.52 | 390（棋盘 340）→ **11.05 px** | ✔ 达标（≥ 10px） |
| 提示 / 判题标记的编号 | 0.5 | 390 → 10.63 px | ✔ 达标 |
| **回放的落子编号** | 0.325 | 390 → **6.91 px**；1440（棋盘 409）→ **8.31 px** | ✘ **不达标**，Phase 04 处理 |

棋盘文字在**最小支持视口下不得小于 10px**。回放编号靠缩小半径换「棋子露在数字外面」，
代价是数字小到读不出——两个目标要重新权衡（放大棋盘、或把编号移到棋子旁边的屏幕坐标层）。

### 8.3 视觉规则（全部保留现状）

- 木纹：`--c-board-a` → `--c-board-b` 线性渐变，配一圈内阴影晕影
- 网格：`--c-grid`，线宽 0.032 格；外框 0.07 格
- 星位：`--c-star`，半径 0.085 格，五个（四角 + 天元）
- 棋子：半径 0.44 格，径向渐变 + 椭圆高光 + 偏移暗圆作假投影（**不用 `filter: drop-shadow`**）
- 最后一手：`--c-danger` 环，半径 0.47 格，带一次 260ms 脉冲
- 胜利连线：`--c-accent`，透明度 0.5，画在棋子**下面**
- 标记：压在棋子之上、命中区之下；三种色调 `accent` / `good` / `bad`

### 8.4 命中

- 整格铺满的正方形，`strokeWidth={0}`（不置 0 会向外多出半格，点正中会落到右下格）
- `touch-action: none` 锁死棋盘，页面其余部分照常滚动

移动端的现实：390px 视口下一格只有 **21.25px**，225 个目标都是 21×21。
物理上不可能满足 44px 建议值（一格 = 棋盘/16，390px 满幅也只有约 24px）。所以**不靠放大命中区**，
靠**落子前的一次确认**——触屏没有鼠标悬停预览，这是当前唯一的缺口。Phase 04 处理。

## 9. 动效

| 名称 | 令牌 | 时长 | 曲线 | 触发 |
| --- | --- | --- | --- | --- |
| `motion-stone-drop` | `--dur-stone` | 180ms | `--ease-entrance` | 刚落下的那一颗（只加给最新一手） |
| `motion-last-move-pulse` | `--dur-pulse` | 260ms | `--ease-entrance` | 最后一手的环 |
| `motion-panel-in` | `--dur-panel` | 160ms | `--ease-entrance` | 弹窗出现 |
| `motion-banner-in` | `--dur-banner` | 140ms | `--ease-entrance` | 判题反馈条 |

时长与曲线都在 `src/index.css` 的 `:root` 里，**按用途命名而不是按大小排刻度**——
全站一共四个动效，造一套 100/200/300 的刻度只会得到三个没人用的值。
`--ease-entrance` 的值就是原先写死的 `ease-out`（`cubic-bezier(0, 0, 0.2, 1)`）：
抽令牌这一步一个数值都没动。

**规则**：

1. 动效只标注「刚刚发生了什么」，不做入场装饰、不做循环播放。
2. `prefers-reduced-motion: reduce` 时必须全部关闭。
3. **`animate-spin` 现在不在降级名单里**——状态药丸的转圈在「减少动态」下照转
   （实测确认）。这是本规范要修的一处：把 `spin` 一并纳入 `@media` 块，
   或改成不依赖动画的静态指示。
4. 150ms 级别的 `transition` 保留：那是最短的状态反馈，关掉会让悬停变成无反馈的跳变。

## 10. 布局与响应式

### 10.1 断点

| 宽度 | 布局 |
| --- | --- |
| < 640 | 纵向堆叠：棋盘 → 对局面板 → 其余 |
| 640–1023 | 纵向堆叠，面板通栏 |
| ≥ 1024 | 三栏（对战）或两栏（教学 / 残局 / 复盘） |

### 10.2 三条硬规则

1. **棋盘优先让位顺序**：先缩面板 → 再折叠面板 → 最后才动棋盘。棋盘不得低于 320px。
2. **侧栏宽度用 `clamp()` 而不是固定 px。** 现在左 268 / 右 344 是写死的：
   1024 时中列只剩 412px（棋盘 362px，视口的 35%），1920 时两侧像是 1308px 空白旁边的两条窄边。
   建议 `clamp(220px, 18vw, 300px)` / `clamp(280px, 24vw, 380px)`
   （已在真实浏览器里试算：1024 下棋盘 362 → 474 px，1440 持平，四档均无横向溢出）。

   **左栏取到 220 px 下限时只剩约 158 px 内宽**——这意味着一行最多放
   **5 个两字标签的极限**就此封死。所以左侧的控件设计必须以「纵向列表」为默认，
   不要指望并排塞下五项（见 FINDINGS 的 F-UI-13）。
3. **面板内部的「标签 —— 值」行不跨整宽拉伸**（768 下标签与值被拉到 744px 的两端，
   视线要来回折返）。窄屏时给这类行设一个最大宽度，或改成上下排布。

### 10.3 顶栏与页面外壳（Phase 01 落地）

```
桌面：[品牌 36×36 + 名称/副标题]  [导航]  ······  [状态条] [主题]
窄屏：[品牌]  ······  [状态条] [主题]
      [导航 —— 等宽四列，铺满整行]
```

- 顶栏 `sticky top-0` + `min-h-15`（60px）：**高度不随页面跳**，导航在窄屏铺满整行。
- **顶栏必须在滚动容器外面**（由 `PageShell` 保证）。列表页在 ≥1024 时滚内层 `main`、
  <1024 时滚文档——把顶栏放进滚动容器，这两种宽度下它的行为就不一样了。
  与正文平级之后，两种宽度都不用 sticky 兜底。
- 导航选中项用 **`bg-accent-soft text-accent`**（底色 + 文字色两层信号，
  不是只靠颜色）。**不用「浮起的白底」**：令牌层级在深色里是
  `surface`(深) → `surface-2`(浅)，同一套类名在浅色下是浮起、到深色就成了凹陷。
  `accent-soft` + `accent` 在两种主题里都是「往前一步」，而且这一对在
  对比度守卫的配对表里。
- 六个页面位置共用 `PageShell` 的两个模式（`reading` / `flush`），见 §10.1。

### 10.4 移动端

- `env(safe-area-inset-*)`：`index.html` 已开 `viewport-fit=cover` 却没有用安全区变量，
  刘海屏横屏会贴边。顶栏与页面底部加上 `padding` 补偿。**（尚未处理）**
- `meta[name=theme-color]` 固定为浅色 `#f6f4f0`，深色主题下移动端浏览器 UI 仍是浅色。
  **（尚未处理）**

## 11. 图标语言

现状混用两套：顶栏用内联 SVG（品牌、主题），其余用文字符号（`←` `→` `›` `✓` `·`）。

**定一条规则**：功能性图标用内联 SVG（`currentColor` + `aria-hidden`），
**方向性符号**（`←` `›`）可以用文字，但必须与文字按钮的标签在同一个可访问名里；
`✓` 这类状态符号要么统一成 SVG，要么明确它是「排版符号」并只出现在文本流里。
不要出现「同一个含义两种画法」。

## 12. 自检清单（每个 Phase 收尾时跑）

```bash
yarn lint && yarn typecheck && yarn test && yarn build && yarn e2e && yarn e2e:prod
yarn ui:probe --out after-phaseNN     # 与 screenshots/before/ 逐张对照
```

`e2e/layout.spec.ts`（Phase 01 新增，28 条）把下面几条变成了可断言的：
棋盘 ≥320px 且是正方形（六档宽度、三个页面）、跨过 `lg` 后棋盘 ≥620px、
页面标题不被压成竖排、滚动后顶栏不位移、顶栏高度跨页面不跳、
导航在 390 下右侧不留空档、文字放大到 200% 不横向溢出。

（`yarn ui:probe` 不带 `--out` 会被拒绝执行——它默认写 `before/`，
而那会把基线覆盖掉。真要重拍基线得显式加 `--force`。）

外加**五条量化判据**，全部能从 `measurements.json` 直接判真假：

1. **`contrastViolations` 全为 0**。
2. **`board` 的宽高在任何状态、任何视口下都 ≥ 320px**
   （Phase 01 之前：教学 / 残局 / 复盘的棋盘长期是 169–409px，命中区最小 11×11）。
3. **`boardRatioOfViewport` 在任何 ≥1024 的视口下不低于 35%**。
4. **`document.horizontalOverflow` 全为 `false`**。
5. **`smallTargets` 里 `under24` 只允许剩下棋盘交叉点**（`rect[intersection-*]`），其余为 0。
   为什么给棋盘开这个口子：一格 = 棋盘/16，390 px 屏幕上即使满幅也只有约 24 px，
   **棋盘永远达不到 24 px 这条线**——而本规范又明令不许放大命中区（§8.4）。
   一条永远红的判据等于没有判据，还会训练人忽略红灯（F-UI-01 就是这么活下来的）。
   棋盘那条安全由判据 2 与 3 单独守。

Phase 05 起再加一条：`reducedMotion.stillAnimating` 为空数组。
