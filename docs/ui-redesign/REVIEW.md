## 1. 会破坏

### R-01 · 统一门槛第 4 条从 Phase 01 起就不可能通过 〔已改〕

**原判据**：`smallTargets` 里 `under24` 全为 `false`。

**为什么做不到**：一格 = 棋盘宽 / 16（`Board.tsx` 的 `viewBox` 是 `1 + 14 + 1`），
390 视口下棋盘 340 px → **21.25 px**，即使满幅也只有约 24 px。
而计划自己明令「不靠放大命中区解决」（DESIGN_SYSTEM §8.4 / Phase 04 风险表）。

**复核**：我把 156 条量测里所有 `under24` 拉出来，只有四类元素——
`rect[intersection-7-7]`（21×21、23×23、**11×11**）与 `收起`/`重试`/`知道了`。
棋盘那一类有 21 条，集中在 390 视口与 F-UI-01 造成的塌陷页。

**处置**：判据改成「`under24` 只允许剩下 `rect[intersection-*]`，其余为 0」，
并把理由写进 `DESIGN_SYSTEM.md` §12 与 `PLAN.md` 的统一门槛。
**一条永远红的判据不只是没用，它会训练人忽略红灯**——F-UI-01 就是这么活下来的。

### R-02 · Phase 01 的 `clamp()` 与 Phase 03 的「难度 5 列」互斥 〔已改〕

**问题**：Phase 01 为把 1024 下的棋盘拉到 45%，左栏要用 `clamp(...,220px,...)`；
而 220 px 左栏扣掉 `px-4`(32) + 边框(2) + `p-3.5`(28) + `p-1`(8) + `gap-1`(16) 后，
5 列每列只有 **26.8 px**，两字标签本身就要 24 px（再加 `px-1.5` 的 12 px 内边距）。

**复核**：实测难度按钮在 1440/1920 上是 **63×28**；按 268 px 侧栏反推内宽 206 px、
5 列每列 36.4 px，而需要 36 px——**刚好卡在临界值**。1024 的 220 px 下必然压盖。
按钮是 `whitespace-nowrap` + `minmax(0,1fr)`，不会换行，只会挤出去。

**处置**：F-UI-13 的修法改成**纵向单选列表**，并写明「5 列方案因与 Phase 01 冲突而排除」；
`DESIGN_SYSTEM.md` §10.2 补一句「左栏取到 220 px 时只剩约 158 px 内宽，
左侧控件以纵向列表为默认」。

## 2. 边界

### R-03 · 棋盘换算基准用错了（16 写成 17）〔已改〕

**问题**：`Board.tsx` 的 `VIEW_SIZE = EXTENT + MARGIN * 2 = 14 + 2 = 16`。
我按 17 折算，导致 F-UI-14 与 DESIGN_SYSTEM §8.2 的整张表都算不出来。

**复核**（这条最该自己发现却没发现）：探针量的 `intersection-7-7` 正好是一格，
四次全部吻合 `棋盘/16`——340→21.25、478→29.88、362→22.63、778→48.63。
`/17` 一列没有一个对得上。**探针早就把正确答案放在数据里了，是我没去核对。**

**处置**：全部重算——坐标标签 0.52 单位 → 390 下 **11.05 px**；
回放编号 0.325 单位 → 390 下 **6.91 px**、1440 下 **8.31 px**；
320 px 棋盘一格 = **20.0 px**；移动端一格物理上限 ≈ **24 px**（原写 26）。
**结论不变**（回放编号不达标），但过程数字不能是错的。

### R-05 · `pointer: coarse` 走 JS 分支，与仓库立场相反 〔已改〕

`ARCHITECTURE.md` 有成文理由反对用 JS 判媒体查询，

不判媒体查询、不需要给 `src/test/setup.ts` 加桩、Playwright 的触摸上下文里天然为真。
**这一条改完比原方案更好**，不是妥协。

### R-06 · Phase 05 的 `plies` 退路不必要 〔已改〕

原风险表写「推不出来就先不改文案」。复核 `search.ts`：算杀分支里
`const forced = findForcedWin(...)` 紧接着就构造返回值，`forced.plies` 与
**已经在用的** `forced.nodes` 同一作用域；一手成五那条捷径 `plies` 恒为 1。

**处置**：改成「加一个 `plies` 字段 + 两处 return，先写失败测试」。
**不留「可能不做」的模糊态**——那句文案是可复现的误导（面板说「直接取胜」，
棋还要走两手）。

### R-07 · `--out` 默认仍是 `before`，防覆盖只靠一句文档 〔已改〕

自审第 1 条宣称「已补上 `--out`」，但补的只是「可以传」；不带它跑一次照样整份覆写基线。

**处置**：探针加闸门——默认目录已存在 `measurements.json` 且没给 `--force` 时
