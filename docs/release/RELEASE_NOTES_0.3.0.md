## 2. 本次变化

- **复盘页「数据管理」**：导出单盘棋谱、全部棋谱、完整本地备份（棋谱 + 学习/残局进度 +
  显示偏好 + 上次对局会话）；导入先预览，只合并不删除。
- **外部格式 v1**：`gomoku-lab.game` 与 `gomoku-lab.backup`，与 IndexedDB 内部
  `schemaVersion` 分开；不把自增 `seq` 当跨设备 ID。
- **严格导入**：文件视为不可信输入；大小/深度/坐标/重复落子/终局后落子/胜负/
  认输语义全部检查；**不复用 `replay()` 的截断**，坏文件不会被悄悄截短。
- **批量事务**：棋谱导入在单个 IndexedDB 事务内去重 + 插入；事务失败整笔回滚。
  打不开库才用内存兜底（明确提示刷新可能丢失）；事务失败明确报「没有写入」。
- **会话迁移**：v1 会话只读迁移到 v2；无法迁移时对战页显示具体原因。
- **未改引擎**：搜索、评估、难度参数、规则、棋盘交互均未变。

## 3. 数据兼容与回滚

- IndexedDB `DB_VERSION = 2`、进度 `1`、棋谱 `1`、会话 `2`，**均未改**。
- 旧进度、旧棋谱、v1 会话均可读取；旧棋谱仍可回放。
- 导入不会删除现有棋谱；进度取并集；偏好/会话默认不覆盖。
- 回滚目标：`d3f5f6cc…`（`0.2.0`）。回滚不会清空 IndexedDB；
  未来若跨 schema 回滚，旧代码会丢弃新格式数据。

## 5. 已知限制

- 只提供合并，不提供替换/清空恢复。
- 10 MiB / 2,000 局上限，无压缩。
- 偏好/会话写 `localStorage`，与 IndexedDB 不同事务。
- 仅 Chrome/Chromium 实测；Safari/Firefox 未验。
- 手动 Wrangler 部署，未启用 Git 自动部署；仍使用 `*.pages.dev`。

## 6. 不要这样解读

- ❌ “0.3.0 提升了棋力” —— 引擎未改。
- ❌ “备份是云同步” —— 文件只在本机生成，用户自己保存。
- ❌ “导入是替换恢复” —— 本阶段只合并不删除。
- ❌ “所有浏览器都验证过” —— 只测了 Chrome/Chromium。
