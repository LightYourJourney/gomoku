# Gomoku Lab 0.7.4 发布说明

**版本**：应用 `0.7.4` / 引擎 `search-1`（搜索决策未变）
**状态**：待发布
**基线**：`0.7.3`（`a45d33b` / 部署 `31c7cd06…`）

## 1. 本次变化

2026-11-27 第三次全量审查的整改，逐条见 [`docs/audit/FULL_REVIEW_2026-11-27.md`](../audit/FULL_REVIEW_2026-11-27.md)。其中 5 条是 0.7.3 那批整改自己引入的，都是「存储暂时不可用」这条罕见路径上的错误，这次按「失败之后恢复」的真实时序逐条复现并修掉。

用户看得到的：

- **数据**：
  - 浏览器暂时存不了数据时，编辑并保存一条已保存的局面，恢复后不会覆盖或删除**另一条**局面。
  - 同一会话里存储反复不可用，也不会因为兜底编号重复而改错记录。
  - 只改标题后再恢复，标题不会被丢掉。
  - 恢复后编辑器仍认得出「最近保存」的那一条。
  - 存储不可用时下完的一局，误点「悔棋」再终局，不再在列表里留下两条。
  - 只存进本次会话的对局，界面说「已存入本次会话」，不再说「没能保存」。
  - 存储降级时**不再拒绝导出**：照常导出屏幕上能看到的全部数据，并写明哪一段含只在本次会话里的记录。配额满时正是需要先导出腾空间。
- **界面**：
  - 窄屏滚动后，偏好保存失败的提示条仍然可见（与顶栏一起吸顶）。
  - 练习的「提示」用完、编辑器的撤销／重做／保存按钮被禁用时，焦点不再掉到页面开头。
  - 练习判错锁盘后，提示不再说「走上去试试」。
  - 数据管理页的导出说明与导入结果不再互相重读。
- **内部**：
  - 纯逻辑层的类型检查新增一道防绕闸门（一行 `@ts-nocheck` 不能再让它失效）。
  - 分层闸门能识别动态 `import()` 与测试库。
  - 跳过用例的检查改为精确计数。
  - 界面探针确认响应来自自己启动的服务器。
