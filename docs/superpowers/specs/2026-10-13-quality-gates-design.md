# 质量门禁（CI + 本地钩子）· 设计

日期：2026-10-13 · 状态：已与用户确认（含一轮独立 builder 检查 + 一轮追问），待实施

## 为什么做这件事

用户的担心不是「现在的代码烂」——现在的代码刚被审计与 UI 重做洗过好几轮
（`docs/audit/` 28 条发现全部有归宿；测试 912 单测 / 100 e2e）。担心的是**衍化过程**：
每加一个阶段，安全网会不会**悄悄缩水**。

这不是假设。UI 重做的 Phase 02 就真的发生过一次：把「显示与声音」改成默认折叠之后，
主题/坐标/音效三颗控件**从所有对比度与命中区扫描里消失**了（基线里扫得到）——
不报错、不红，只是不再被检查。抓到它，靠的是**有人记得重跑探针对比基线**。

**缺的不是检查，是「没人跑就不会跑」。** 目前仓库里**一个 workflow 都没有**，
远端是 GitHub（`LightYourJourney/gomoku`）。

## 目标

1. **本地 pre-push 跑快档**：红了推不出去。
2. **GitHub Actions 跑全档**：快档 + e2e + e2e:prod + `ui:probe` + bench 数值门禁。
3. **三个防退化闸门**：循环依赖、死代码 / 未用导出、重复代码。
   外加**两把覆盖棘轮**：探针扫到的状态/控件、测试条数——只许涨不许跌。
4. **基准门禁**：把「性能悄悄退化」变成会红的东西——且**不制造假红**。

## 非目标

- 不借机加新的 lint 规则或提高现有检查的严格度。
- 不做覆盖率门禁。这个仓库的立场是「断言有没有鉴别力」比覆盖率重要
  （`TEST_GAPS.md` 记的就是这条），覆盖率数字会引导错的努力方向。
- 不引 SonarQube 一类需要服务端的重型工具。
- **不动 main 的工作流**：仍是「分支上做完 → 本地 ff-merge → 手动 push」，不改 PR 流程。

## 反目标（技术上跑通了也算失败）

| 反目标 | 为什么 | 对策 |
| --- | --- | --- |
| 闸门一上来一片红 | 会训练人忽略红灯 | 三个工具先实测；真问题修掉、可接受的进基线并**写明理由** |
| 基准门禁变成假红制造机 | 同上，且这条最隐蔽 | **只断言余量充足的行**（见下），跳过项**打印原因** |
| 快档慢到让人习惯 `--no-verify` | 等于没有门禁 | 快档实测 ~36 秒（热），预算 1 分钟 |
| CI 首跑没验过就开全档 | 红了分不清是环境还是代码 | **分两步开**：先只跑快档，绿了再打开全档 |
| 「一条永远不红的判据」 | 等于没有判据 | `ui:probe` 已会非零退出；CI 里不得改成只采集 |

## 已定的选择（用户拍板）

- **形式**：本地 pre-push 钩子（快档）+ GitHub CI（全档）。已知代价：`--no-verify` 可绕过，接受。
- **范围**：现有检查 + 防退化检查 + 基准阈值。
- **`ui:probe` 的 rollout**：**首跑先只看数**（把 Linux 上的量测打出来但不阻断），
  **第二次起当闸门**。拿到数再判断差异是噪声还是真的 Linux 布局问题——那时才动产品。

## 实测证据（决定方案形状）

三个工具用一次性 `npx` 跑过，**当时没有装进 `package.json`**：

| 工具 | 今天的结果 |
| --- | --- |
| `madge --circular` | **零循环**，136 个文件 |
| `knip` | 11 条：1 个真·多余导出（`src/learn/verify.ts` 的 `OK` 只在本文件用却导出了）、9 个「只被签名引用」的类型导出、1 对同义常量 |
| `jscpd --min-tokens 50 --ignore "**/*.test.*"`（范围 `src/`） | **4 处克隆 / 重复行 0.84%** |

**同一个仓库、同一份代码，`npx` 两次跑出的 knip 结果就不一样**（一次 9 个未用类型导出、
一次 10 个）——所以工具必须钉版本，见「依赖」。

`ui:probe` 的两件事也验过：

- **它会红**：违反 `DESIGN_SYSTEM.md` §12 的五条判据时 `process.exitCode = 1`
  （`bench/ui.probe.mjs` 末段）。脚本自己的注释写着「采集不等于判定。一条永远不红的判据
  等于没有判据，这个仓库已经为此吃过亏」。
- **它不能裸跑**：不带 `--out` 时写 `before/`，而那份 `measurements.json` 是入库基线，
  脚本会**拒绝开跑并退出 2**。CI 里必须写 `--out <目录>`。
  **但它不需要外部 dev server**——它自己在 **5184** 起一个（`bench/ui.probe.mjs:26`）。
  写计划时这里也错过一次：原本写「先有 dev server 起着」，那不但多余，
  真在 5181 起一个还会让 Playwright 的 `webServer`（CI 里 `reuseExistingServer=false`）
  因端口被占直接失败，**e2e 会无缘无故红**。

## 基准门禁：只断言余量充足的行

`AI_ENGINE.md` 的稳定性结论是**同一台机器上**得出的。把基线产物逐行量过之后是这样：

| 档位 | 局面 | 耗时 | 预算 | 占比 | 基线判定 |
| --- | --- | --- | --- | --- | --- |
| hard | 双三 | 1601 | 1600 | 100% | timeout |
| expert | 开局 / 中盘 / 双三 | 2601–2602 | 2600 | 100% | timeout |
| **hard** | **开局** | **1101** | 1600 | **69%** | search |
| **hard** | **中盘** | **921** | 1600 | **58%** | search |
| 其余 14 行 | | ≤212 | | **≤12.3%** | search |

**问题**：拿「所有 search 行」当门禁，在一个比这台 Mac 慢 1.45 倍的 runner 上，
hard 那两行会翻成 `timeout` → 节点数变化 → **代码没改却红**。这正是反目标 #2。

**做法**：

- **断言集**＝基线耗时 **≤ 预算 20%** 的行（≥5 倍余量）→ 14 行 search ＋ 5 行 `win`。
  那 5 行 `win` 的 depth/nodes 恒为 0，但它们钉的是「这一手能直接成五」这个
  **棋型识别不变量**，价值不在数字大小。
- **跳过集**＝4 行 timeout ＋ hard 的两行，**跳过时逐行打印为什么跳过**。
- 被断言的行如果**跑成了 timeout**（或 depth/nodes 对不上）→ **响亮地红**，
  报错里要区分「算法变了」与「机器慢到没搜完」。
- 断言集**由基线文件决定**（每行带 `gated` 标记），不由当次运行的 `reason` 决定——
  否则「search 翻成 timeout」这一种退化会被静默跳过。
- 基线是**入库的、显式的**文件；要更新它＝显式改文件，改动进 diff、有人看得见。

## 两把覆盖棘轮：把「覆盖缩水」变成会红的

**这是本设计最初漏掉的一半，而且恰好漏的是用户最担心的那半。**

先说清楚原来漏在哪：`bench/ui.probe.mjs` 的 `checkCriteria(rows)` 只吃**本次扫到的行**
（`:1037`），板子量不到时**直接跳过判据**（`:1048`），而全仓唯一读既有
`measurements.json` 的地方（`:826`）是「拒绝覆盖基线」的守卫，**不是比对**。
所以从 `STATES` 里删掉一个状态、或某颗控件从 DOM 里消失 → 探针少几行量测 → **全绿**。
**Phase 02 那次事故的形态可以原样复现。**

换句话说：门禁把「没人跑」变成了「机器会跑」，但**没有把「覆盖缩水」变成会红的**。

**做法：棘轮（ratchet）——本次覆盖必须是入库基线的超集，少一条就红。**
不引任何新工具，两把都建在既有产物上：

| 棘轮 | 判据从哪来 | 基线 |
| --- | --- | --- |
| 覆盖棘轮 | `ui.probe` 已经写进 `measurements.json` 的 `state/size/theme/buttons/headings` | `quality/coverage.baseline.json`（172 条 / 21 状态） |
| 条数棘轮 | `yarn test` 落盘的 `vitest-report.json` + `playwright test --list` | `quality/tests.baseline.json`（912 / 0 / 0 / 102） |

三条设计约束：

- **只查「不能少」，不查「不能多」**——新增覆盖是好事，棘轮不是锁。
- **读不到产物就响亮失败**，不许静默跳过（静默跳过＝一条永远不红的判据）。
- 失败文案要点名到**哪个状态、哪个尺寸、丢了哪颗按钮的什么文案**——
  报错读不懂，人就会去 `--no-verify`。

**代价（写下来，别装看不见）**：以后合法地删状态、改用例名、增删控件，
都要顺手更新那份基线。**这正是目的**——把「安全网变小」变成一个进 diff、有人看得见的决定。

## 三个防退化闸门

| 闸门 | 工具 | 判据 |
| --- | --- | --- |
| 循环依赖 | `madge --circular` | 有环即红（今天零环，无历史包袱，不设容忍） |
| 死代码 | `knip` | 用 `ignoreExportsUsedInFile` 按**符号种类**放行「只被签名引用」那一类；剩下那对同义常量用 `ignoreIssues`（**不是** `@public`——knip 报的是 `duplicates`，`@public` 管的是「未被使用的导出」，对它无效）。不塞 blanket ignore |
| 重复代码 | `jscpd --min-tokens 50` | 范围＝`src/` **且排除测试文件**；**阈值 0**，接受的同形逐个文件显式豁免。**只认逐字相同的克隆** |

**jscpd 的范围与阈值是刻意的**：

- 0.84% 这个数只在该范围下成立（含测试是 2.35%；仓库根 2.32%）。
  **排除测试是政策决定**：测试里重复夹具是合理的，为通过闸门去写更差的测试是本末倒置。
- **阈值设 0：零容忍**。今天那 4 处被接受的同形**逐个文件写进 `ignore`**，理由进 `TECH_DEBT.md`。

  > 写实施计划时这里改过一次主意，记下来免得两份文档各说各话：原本写的是
  > 「阈值不设 0，但每次打印克隆清单」。**打印清单不会有人看**——
  > 「0.84% 悄悄涨到 0.95%」正是这种"看得见但没人看"的东西。
  > 改成零容忍 + 显式豁免之后，**「接受一处重复」变成一个进 diff 的决定**，
  > 而不是一个百分比阈值替你做的决定。代价写明：被豁免的那几个文件
  > 从此不受这道闸门保护。
- 将来新写一个与现有页面同形的页面会被拦下。**这是要的效果**：
  「这是重复，还是两种东西长得像」必须有人做一次判断；
  判断是"长得像"就显式加进豁免并在文档里写理由，是"重复"就去合并。

**jscpd 的能力边界（实测，不是推测）**：它是**复制粘贴检测器，不是「重复实现」检测器**。
逐字复制会红；**把所有标识符改名、结构完全保留则不红**（实测 `Found 1 clones` → `Found 0 clones`）。
所以「把一份东西抄成两份再改改名字」这套闸门抓不到——这条要写进 README，
免得让人以为挂上它就不会再有重复实现了。

**knip 的基线**指向 `TECH_DEBT.md` §1.3 已裁定「明确不偿还」的那一类；
顺带修掉 `verify.ts` 的 `OK`（去掉 `export`，它只在本文件用）。

## 依赖

**三个工具钉成 devDependencies**（精确版本），不用 `npx`：

- pre-push 钩子不该依赖网络；
- 版本漂移会改变结果（上面已经观察到 9 vs 10）；
- 闸门变红必须能归因到**代码**，不是工具。

**不引 husky**：用仓库内的 `.githooks/pre-push`，在 `package.json` 的 `prepare` 里加一句
`git config core.hooksPath .githooks`——`yarn install` 时自动挂上。
