# 候选预筛（Candidate Pre-screen）· 设计与实验方案

**日期**：2026-10-31
**状态**：方案定稿，实现未开始（先做实验，未拿到棋力证据不合入）
**依据**：[OPTIMIZATION_CANDIDATES.md](../../ai-research/OPTIMIZATION_CANDIDATES.md) §1、[CPU_PROFILE.md](../../ai-research/CPU_PROFILE.md)、[SEARCH_OPTIMIZATION.md](../../ai-research/SEARCH_OPTIMIZATION.md)

## 1. 要解决的问题

排序占固定深度剖面 **七成以上**（Phase 10C 后 `scanDirection` 38.5%、`analyzeFast` 8.5%）。
一次 `orderMoves` 平均给 **56.1 个候选**打分，而宽度只有 12（hard）/ 14（expert）——
**约 78% 的打分在 `slice(0, width)` 时被丢掉**。

目标：在**不改变搜索结果正确性**的前提下，把参与完整打分的候选压到 2×width 左右，
把端到端耗时再压 1.25–1.35×。这是当前唯一有量级空间的方向。

## 2. 非目标

- 不改评估函数、不改棋型表、不改难度参数。
- 不做 VCT、不做时间管理改造——它们各自是独立课题。
- 不以节点数变少当成功判据；唯一判据是**棋力不降**。

## 3. 正确性红线（先立判据，再动手）

排序直接决定谁进入搜索，任何代理指标都可能漏掉关键着法。三条红线：

1. **立即成五不得被筛掉。** 现在 `orderMoves` 在打分的同一遍里用
   `analyzeFast(...).five` 判定「这一步能不能直接赢」，命中就返回 `winNow`。
   预筛先于完整分析，就必须有一条**独立的、更便宜的成五检测**，且必须证明
   它与 `analyzeFast().five` 在大量随机局面上逐位一致（见 §5 等价测试）。
   合入前撤掉预筛开关时，所有行为快照必须逐位相同。
2. **置换表着法与杀手着法永不参与预筛。** 它们带的是跨节点的信息，不是本节点的棋型分。
3. **预筛只在候选数超过阈值时启用。** 候选 ≤ 24 时没有收益，直接走原路径，
   保证低分支节点的行为完全不变。

## 4. 设计

### 4.1 开关与参数

`SearchOptions` 增加一个可选字段（**默认关闭**，生产不传）：

```ts
readonly prescreen?: {
  /** 候选数超过它才启用；≤ 它走原路径。 */
  readonly threshold: number
  /** 保留的候选数 = width × keepFactor。 */
  readonly keepFactor: number
}
```

- 开关关闭时：代码路径与现在**逐字节相同**，`search.equivalence.test.ts` 的四个固定
  深度快照一个数字都不能变（这是本项目的性能优化红线）。
- 开关打开时：快照会变——这是策略变更的**预期结果**，不是回归；因此等价测试
  只保护「关闭态」。

### 4.2 预筛信号（便宜且与棋型弱相关）

按三个可加项排序，全部是 O(1)–O(邻居数) 的操作，不调用 `analyzeFast`：

1. **邻域密度**：以该点为中心的 5×5 内双方棋子数（一个 5×5 窗口最多 25 次读）。
2. **最近棋子距离**：到最近棋子的切比雪夫距离（距离 2 以外基本不可能是好点）。
3. **方向潜力**：沿四个方向各数 3 格内同色/异色棋子数，作为「这一带有没有战场」的粗信号。

保留 `keepFactor × width` 个（hard 24 / expert 28），其余丢弃。阈值与系数都通过
`prescreen` 参数注入，不写死——实验要扫参数。

### 4.3 立即成五的独立检测

新增 `completesFive(board, point, player): boolean`（纯函数，`ai/patterns.ts` 旁）：

- 只做四个方向的定长扫描（最多 9 格），不看三/四型、不建 9 字节缓冲。
- 测试要求：在 ≥ 5,000 个随机局面 × 全部空点上与 `analyzeFast(board, point, player).five`
  逐点相等；失败时打印棋盘与坐标。
- 与预筛解耦：即使预筛关闭，这一个函数也可以被 `orderMoves` 复用（但**先不合入**，
  避免一次改动两个变量）。

### 4.4 装配顺序（`orderMoves` 内部）

```
1. 若 prescreen 关闭 → 现状代码路径（不动一行）
2. 否则：
   a. 对全部候选做 completesFive；命中 → 直接返回 winNow（与现状同义）
   b. 把 tableMove / killers 从候选集里摘出（永不筛）
   c. 其余候选按 §4.2 打分，保留 keepFactor×width
   d. 对保留集跑现有 analyzeFast + threatScoreWith 完整打分
   e. 与 a 步摘出的着法合并、排序、slice(0, width)
```

## 5. 验证协议（按顺序，缺一步都不算数）

1. **等价测试（关闭态）**：`yarn test` 中 `search.equivalence.test.ts` 四个快照逐位不变。
2. **成五检测等价**：§4.3 的 5,000 局面差分测试通过。
3. **行为差异量化**：固定深度跑 20 个开局 × 双方，记录「开/关」的着法差异率、
   节点数、耗时。差异率本身不是判据，只是解释后面棋力结果的材料。
4. **棋力 A/B（唯一判据）**：`yarn strength` 配对赛，同开局双方各执黑一次：
   - `STRENGTH_MODE=standard` 至少 200 局，`extended` 复核；
   - 判据：**开与关的胜率差落在噪声范围内**（用现有报告的置信区间），
     且**平均每步耗时显著下降**。
   - 任何一次「开了之后明显变弱」→ 直接放弃，不调参数救。
5. **剖析**：`yarn profile` 记录 `orderMoves` / `orderCandidates` 占比变化，
   写进 CPU_PROFILE 的更新节，注明机器负载。

## 6. 决策点（拿到数据后由用户定）

| 结果 | 动作 |
| --- | --- |
| 棋力持平、耗时降 ≥15% | 默认打开，参数写进 `difficulty.ts` 的每档配置；等价快照重新基线化并注明原因 |
| 棋力持平、耗时降 <15% | 不合入（复杂度不值得），结论写进 OPTIMIZATION_CANDIDATES |
| 棋力下降 | 放弃该方向，转「滑动窗口化 scanDirection」 |

## 7. 风险

- **成五漏检**是本方案唯一的灾难性失败模式；§4.3 的差分测试是它的唯一闸门，
  必须先在**旧实现**上跑红一次（构造一个只差一手的局面）再跑绿。
- 预筛参数过激会让中局战术变差，而配对赛对「偶发漏杀」不敏感——因此
  `STRENGTH_MODE=extended` 必须复核，不能只跑 standard。
- 与增量评估叠加时的相互影响未测；实验期间不动增量评估。
