## 一、会丢数据或判错的缺陷

| # | 问题 | 位置 | 处置 |

| 2 | 每个新的兜底实例都从同一基数发号，而映射表永不清空：同一会话两次「库不可用」后，新记录拿到旧号，保存会覆盖库里的另一条局面 | `persist/positions.ts`、`persist/gameRecords.ts` | 每个兜底实例占一个独立号段（`FALLBACK_*_STRIDE`），映射表只在不冲突的前提下保留；换存储工厂时清空映射 |

## 二、质量闸门

| 问题 | 处置 |
| --- | --- |
| 「纯逻辑层无 DOM 类型检查」可被一行 `// @ts-nocheck` 或 `/// <reference lib="dom" />` 完全解除（实测） | 新增 `check:suppressions`（`quality/no-ts-suppressions.mjs`，在 `gates` 里）：纯逻辑层四层生产文件禁 `@ts-nocheck` / `@ts-ignore` / `@ts-expect-error` / 三斜线 reference；`@ts-nocheck` 在 `src` 全范围禁。扫描范围取 tsconfig.pure 的 include 与四层固定目录的并集，缩小 include 也躲不掉 |
| 分层闸门三条静默通道（实测）：非字面量 `await import(t)` 放行；字面量动态 import 被同文件 `import type` 掩盖；纯逻辑层 import `@testing-library/react` 也绿 | 按 TS AST 解析动态 `import()`；字面量按路径过允许表并计入「非仅类型」；非字面量在纯逻辑层直接红；禁用名单补 `@testing-library`、`@playwright`、`vitest`、`jsdom`、`fake-indexeddb` |
| 运行期跳过检查只拦「0 条真跑」，`--grep` 跑一条也能过（实测） | 按文件名映射到基线键（e2e / e2e-prod / browsers / browsers-full），`expected + skipped + 预期失败` 必须精确等于期望值；逐条数还要与统计相符 |
| 界面探针端口探测与启动之间有 TOCTOU，可能测到别的工作树 | 用 `lsof` 取监听 PID（查不清失败关闭）；直接 spawn vite 的入口使监听 PID = 子进程 PID；200 之后 PID 必须匹配，否则继续等或超时并打印两个 PID |

## 自审记录

1. **降级时不拒绝导出，会不会产出一份「看着成功、其实缺数据」的备份？** 备份里各段形状不变，空段本来就能表达；缺哪一段在导出说明里写出来（「棋谱含只在本次会话里的记录」「局面含……」），而且这正是用户需要拿去腾空间的那些数据。空库仍报「棋谱库是空的」，不产出空文件。
2. **只进内存的那一局标成 `session` 而不是 `failed`，会不会让人以为「存好了」？** 文案是「已存入本次会话（浏览器暂时存不了数据，刷新页面后就没了）」，说的是事实；`failed` 用在真的没存下（事务失败且没有兜底）的场合。`recordedSeq` 照样记下兜底号，替换链因此接得上。
3. **每个兜底实例换号段，映射表会不会无限增长？** 只会在「降级 → 补写」反复发生时增长，量级是一次会话几次；换存储工厂（测试）时清空。相比撞号导致改错数据，这个代价可以接受。
4. **`check:suppressions` 会不会误伤合法的 `@ts-expect-error`？** 先 grep 全仓，纯逻辑层零处合法用法，所以四层全部禁止；`src` 其余地方只禁 `@ts-nocheck`。
