# 基线棋力测量（Phase 10A）

> **先说清楚这不是什么**：这不是「五档棋力排名」，也不是「Elo 等级」。
> 这里只有三次**小样本**实测，用来证明评测系统能跑通、能分辨强弱、能公平对照。
> 置信区间很宽，任何「X 档比 Y 档强 N 分」的说法都超出了数据支持的范围。

日期：2026-10-20 ｜ 环境：Apple Silicon（arm64）/ 8 CPU / Node v26.12.0 / 提交 `c24c7f8`（工作区含未提交改动）
原始报告：[`runs/`](runs/) ｜ 协议：[`BENCHMARK_PROTOCOL.md`](BENCHMARK_PROTOCOL.md)

## 1. 冒烟：入门 vs 初级（真实预算）

| 项 | 值 |
| --- | --- |
| 模式 | smoke（2 开局 × 2 局 = 4 局） |
| 预算 | 入门 250 ms / 初级 500 ms |
| 结果 | A（入门）2 胜 / B（初级）2 胜 / 0 和 |
| 得分率 | **50.0%**（CI 50.0–50.0%） |
| 全部 4 局的胜方 | **执黑方** |
| 工时 | 0.2 秒 |
| 实测深度 | 入门 0.80，初级 1.60（各自达到深度上限后即停，远未用满预算） |

**这组数字的价值在方法而不在棋力**：4 局全部由执黑方获胜，说明先手优势足以
盖过两档之间的差距。若不配对，随便让一方执黑就能「证明」它更强。

## 2. 确定性配置对照：固定深度 2 vs 4

| 项 | 值 |
| --- | --- |
| 模式 | standard（4 开局 × 2 局 = 8 局） |
| 配置 | A = medium，`clock: fixed`，`maxDepth: 2`；B = medium，`clock: fixed`，`maxDepth: 4`（**从独立打包的引擎包加载**） |
| 结果 | A 1 胜 / B 6 胜 / 0 和 / **1 局达到手数上限** |
| 得分率 | **14.3%**（95% CI **0.0–37.5%**） |
| 工时 | 5.0 秒 |
| 实测深度 | A 1.41（受广度与置换影响，未每层都到 2）；B 2.67 |

这组是**算法层**的对照：时钟固定、深度固定，结果逐手可复现。
B 的胜率明显更高，且 B 是**通过引擎包加载**的——同时验证了版本对照的加载链路。

那一局 `move-limit` 没有被算成和棋（`scored = 7 / 8`），这正是协议第 4 条要防的事。

## 3. 真实预算：中级 vs 高级

| 项 | 值 |
| --- | --- |
| 模式 | smoke（2 开局 × 2 局 = 4 局） |
| 预算 | 中级 1000 ms / 高级 1600 ms |
| 结果 | A（中级）1 胜 / B（高级）3 胜 / 0 和 |
| 得分率 | **25.0%**（95% CI **0.0–50.0%**） |
| 工时 | 83.3 秒（负载均值 3.22） |
| 实测深度 | 中级 2.84、高级 3.72 |
| 平均节点 | 中级 543、高级 5 481 |
| 超时回退 | 中级 0 / 86 手；高级 **24 / 87 手** |

两点值得记录：

1. **高级并非全胜**：`center-diagonal` 那一局，高级执黑却输给了中级执白。
   小样本里出现这种结果是正常的，也说明不能凭单局下结论。
2. **高级档约 28% 的着法吃满了预算**（24/87，`reason === 'timeout'`），说明
   1600 ms 对深度 6 来说偏紧——这是后续优化的候选热点，不是本阶段的结论。

## 4. 如何复现

```bash
# 冒烟
yarn strength

# 确定性对照（固定深度）
STRENGTH_MODE=standard STRENGTH_A=medium STRENGTH_A_FIXED=2 \
STRENGTH_B=medium STRENGTH_B_FIXED=4 yarn strength

# 真实预算对照
STRENGTH_MODE=smoke STRENGTH_A=medium STRENGTH_B=hard yarn strength

# 与历史版本对照
git worktree add /tmp/gomoku-base <commit>
node bench/strength/bundle-engine.mjs --root /tmp/gomoku-base --out bench/strength/.engines/base.mjs
STRENGTH_A=hard STRENGTH_B=hard STRENGTH_B_MODULE=bench/strength/.engines/base.mjs yarn strength
```

## 5. 统计局限

- 每组只有 4–8 局，置信区间宽到只能区分「明显更强」与「没有明显差别」。
- 置信区间以**开局为簇**重采样；开局只有 2–4 个，簇数少时区间本身也不稳定。
- 真实预算的结果依赖机器速度与负载；换机器后**不能**直接比较绝对数字，只能在同一环境下重跑。
- 没有人类对局基准，因此**不能**把五档映射到「人类几级」。
- 三次实验用的开局集不完全相同（smoke 2 个、standard 4 个），三组之间不构成一条完整的梯子。

## 6. 当前能说的结论

1. 评测器能跑完整对局、正确分类结局、按配对赛抵消先手优势。
2. 固定深度 2 → 4 带来可观测的棋力提升（14.3%，CI 上限 37.5%），说明「加深」这条方向是有效的。
3. 真实预算下高级对中级 **小样本**占优（25% vs 75%），但样本不足以给出精确差距。
4. 高级档约 28% 的着法吃满预算（24/87），深度上限 6 未稳定达成（平均 3.72 层）——这是下一步的候选优化点。

**不能说的**：五档的完整强弱排序、任何一档的 Elo 值、与人类棋手的对应关系。
