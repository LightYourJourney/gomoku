# 棋力评测协议

本文件定义 **Gomoku Lab AI 怎么测、什么算数、什么不算数**。
它是评测代码的规格说明；代码在 `bench/strength/`，自测在 `bench/strength/*.test.ts`。

> 一句话原则：**先证明测量是对的，再相信测量结果。**

## 1. 两种模式，不可混用

| | 确定性算法评测 | 真实棋力评测 |
| --- | --- | --- |
| 时钟 | 固定为 0（`clock: 'fixed'`） | 真实 `Date.now`（`clock: 'real'`） |
| 约束 | `maxDepth` 显式给定 | 难度自带的 `budgetMs` |
| 可复现 | 逐手完全一致 | 依赖机器与负载，不可逐手复现 |
| 回答的问题 | 搜索结构是否改变、剪枝是否有效、战术是否找得到 | 五档之间、版本之间谁更强 |
| **不能**回答 | 正式难度下的棋力 | 固定深度下的算法差异 |

`assertSpec()` 在开跑前拦截两种混淆：

- `clock: 'fixed'` 却没给 `maxDepth` → 报错（否则深度沿用难度上限，报告会误导）；
- `clock: 'real'` 却给了 `maxDepth` → 报错（那测的是固定深度，不是正式棋力）。

**报告里两种模式分别标注**，`BASELINE_STRENGTH.md` 也不会把两者放进同一张对比表。

## 2. 标准局面库

`bench/strength/positions.ts`，16 个局面，13 个类别：

| 类别 | 代表局面 | 可证明的性质 |
| --- | --- | --- |
| `empty` | 空盘 | 开局走天元 |
| `opening` | 贴身 / 斜向 / 马步应手 | 双方都没有立即成五点 |
| `quiet` | 安静中盘 | 同上 |
| `direct-win` | 横四两端开 | 存在成五点 |
| `rush-four` | 冲四（一端被堵） | 存在成五点（唯一） |
| `must-block` | 单一威胁 / 活四 | 对手有成五点；单威胁时只有一个不立即输的点 |
| `multi-win` | 横四 + 竖四 | 多个成五点 |
| `open-three` | 活三 | 无立即成五，但存在三步强制胜 |
| `double-threat` | 十字双三 | 三步强制胜 |
| `forced-win` | 带干扰子的活三 | 三步强制胜 |
| `threat-not-win` | 我方活三 + 对方冲四 | 只有堵那一点不立即输（威胁不构成必胜） |
| `transposition` | 同一盘面的两条手顺 | 两条合法手顺重放出同一盘面 |
| `endgame` | 接近满盘（8 个空位） | 无五连 |

### 2.1 「预期」是可证明的性质，不是引擎的输出

**不允许**拿引擎某次运行的结果当标准答案再用同一引擎验收。局面库只声明三类可独立验证的性质：

1. **规则层**：是否已有五连、某方是否有成五点、合法落子；
2. **独立证明器**（`proof.ts`）：存在「我方走一步 → 对手任意应手 → 我方仍能成五」的强制胜，只依赖 `core/rules.ts`，不调用搜索引擎；
3. **可复核棋型**：人工能看懂的横四、活三、十字。

证明器只证 **3 手强制胜**。证不出来**不等于**不存在——更长的链需要真正的搜索，那会让证明器变成第二个引擎，失去独立性。

### 2.2 可达性：`synthetic`

真实对局黑白交替，子力数最多差一枚。战术局面（如「黑有四子、白一子都没有」）**不可能由合法手顺到达**，因此显式标 `synthetic: true`：

- 它们不是「非法棋盘」（格子合法、无五连），只是不可达；
- 只能用于战术探针，**不得作为对局起点**——对局起点全部来自 `openings.ts`，每条手顺由 `replay()` 验证；
- `positions.test.ts` 有一条用例**按盘面**比对「synthetic 局面不出现在开局集里」——比 id 更严：id 不同但盘面相同同样算混用。

### 2.3 自检

`positions.test.ts` 逐条验证：无既存五连、非 synthetic 局面子力守恒、声明的性质全部成立、id 唯一、类别覆盖齐全、开局合法且未分胜负、开局覆盖至少 4 种白棋应手且含非天元首手；`transposition` 局面还要逐条 `replay()` 它记录的 `orders`，确认两条手顺真的落在同一盘面上。

## 3. 公平赛制

### 3.1 成对设计

每个开局跑**两局**：

- 第 1 局：A 执黑、B 执白；
- 第 2 局：B 执黑、A 执白。

只跑一局的话，测到的是「谁执黑」而不是「谁更强」——五子棋先手优势足够大到能主导结果（见 `BASELINE_STRENGTH.md` 的实测）。

### 3.2 开局集

`bench/strength/openings.ts`，8 条固定手顺：贴身、斜向、马步、远角、非天元首手、两个四手分叉、一个六手起点。

- 全部由 `replay()` 验证：合法、未分胜负；
- 开局集是**实验的一部分**，改动它等于换了一组实验，历史结果不能直接比；
- 报告记录每条开局的完整手顺。

### 3.3 保持不变的条件

同一组实验内：同一台机器、同一进程、串行执行、相同手数上限、相同终止规则。真实预算下仍会有负载波动，因此报告记录负载均值与环境信息。

## 4. 结局分类

| 结局 | 计入胜率 | 说明 |
| --- | --- | --- |
| `black-win` / `white-win` | ✅ | 规则判定的胜负 |
| `draw` | ✅（0.5） | 棋盘填满且无人成五 |
| `move-limit` | ❌ | 达到实验手数上限，**不是和棋** |
| `aborted` | ❌ | 实验墙钟超时 |
| `illegal-move` | ❌ | 引擎给出非法着法（最严重缺陷，保留局面与手顺） |
| `no-move` | ❌ | 盘面未满却返回 `null` |
| `engine-error` | ❌ | 抛错，或**修改了传入的棋盘** |

未完成与异常单独成表。把它们并进和棋会让「引擎走不完一局」看起来像「势均力敌」。

## 5. 统计

- **得分率** = (胜 × 1 + 和 × 0.5) / 计分局数。
- **置信区间**：配对 Bootstrap，**以开局为簇**重采样（同一开局的 A-黑 / B-黑两局共享局面与对手，按单局重采样会把区间算得偏窄）。
- **随机种子固定**，同一份数据两次跑出相同区间。
- **描述性 Elo**：`-400 × log10(1/p - 1)`，仅在 `0 < p < 1` 时给值。它假设固定棋力差，**小样本不能当客观等级**。
- **搜索指标**：平均/中位/最大节点、平均深度、平均耗时、`ttHits`、超时次数、捷径次数，按引擎分别统计；阶段划分为开局 1–20 手、中盘 21–60 手、后期 61 手起（按**绝对手数**，开局已走的几手计入）。

### 5.1 与历史报告比较

`STRENGTH_BASELINE=<历史报告的 .json>` 会让本次报告多出一节「与基线比较」：

- **双方 id 完全相同**时才计算差值（`本次 A 得分率 − 基线 A 得分率`）；
- 对手不同（id 不同）时**不给差值**，只列出基线数值并注明「不同对手的得分率不可相减」。

这条不是保守，是因为得分率是**相对**指标：对初级得 80% 与对专家得 40% 之间没有可比性。

## 6. 版本对照

**必须能比较两个不同版本的引擎**，而不是只让当前源码的不同参数互打。

做法：把目标源码树的引擎打成独立 ESM（`bundle-engine.mjs`），评测时动态加载。

```bash
# 当前源码
node bench/strength/bundle-engine.mjs --root . --out bench/strength/.engines/current.mjs

# 历史版本
git worktree add /tmp/gomoku-base <commit>
node bench/strength/bundle-engine.mjs --root /tmp/gomoku-base --out bench/strength/.engines/<commit>.mjs

STRENGTH_A=hard STRENGTH_B=hard STRENGTH_B_MODULE=bench/strength/.engines/<commit>.mjs yarn strength
```

- 两版**零共享**：旧版本有自己的 `search.ts` 与 `difficulty.ts`；
- 共享的只有协议（`Engine.choose` 的返回形状）；
- 报告记录每个引擎包的 SHA-256 指纹；
- 包返回的 `id` 与配置不一致时**开跑前报错**，避免产出一份署错名的报告；
- `engines.test.ts` 验证「当前源码打包后与进程内引擎逐局面给出相同着法」，钉住打包入口与 `local.ts` 的等价性。

## 7. 规模与成本

| 档次 | 开局 × 重复 | 手数上限 | 实测成本 |
| --- | --- | --- | --- |
| smoke | 2 × 1（4 局） | 80 | 入门 vs 初级 **0.2 秒**；中级 vs 高级 **82 秒** |
| standard | 4 × 1（8 局） | 120 | 固定深度 2 vs 4（medium）**5 秒** |
| extended | 8 × 2（32 局） | 160 | 未跑；按 standard 的每局耗时外推 |

**CI 只跑确定性评测器的单元测试**（`bench/strength/*.test.ts`，约 0.6 秒），不跑真实对局。强度评测独立触发。

## 8. 可追溯性

每份报告包含：commit、工作区是否脏、引擎版本、Node / 平台 / 架构 / CPU 数、开始与结束时间、耗时、模式、命令、双方配置与指纹、开局手顺、手数上限、重复次数、完整逐局数据、统计方法、搜索指标、异常。

结果写 `bench/strength/results/<UTC 时间>-<A>_vs_<B>.{json,md}`，**文件名带时间戳，不覆盖**（同一时间戳撞名时退到 `-2`、`-3`）。该目录 gitignore。

需要长期保留的实验，把 **JSON 与 MD 一起**抄到 `docs/ai-research/runs/`——只抄 Markdown 会丢掉逐手数据。查看方式与 schema 差异见 [`runs/README.md`](runs/README.md)。

## 9. 本协议不证明什么

- 不证明「五档接近人类某水平」——没有人类基准；
- 不证明「赢了某个对手就等于强多少 Elo」——单个对手、几十局，只能说明相对关系；
- 不证明「真实预算下可复现」——只保证同条件重复实验的统计可比；
- 不覆盖战术之外的能力（布局长期规划、心理、时间管理）。
