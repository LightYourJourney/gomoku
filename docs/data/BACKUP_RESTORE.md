# 备份、导出与恢复

## 1. 入口

复盘页顶部「数据管理」面板：

- **导出全部棋谱**：一份只含 `games` 的备份文件。
- **完整备份**：棋谱 + 学习/残局进度 + 显示偏好 + 上次对局会话 + 自定义局面。
- **导入文件**：单盘棋谱或上述两种备份。
- 每条棋谱右侧的**导出**：单盘 `gomoku-lab.game` 文件。

所有文件都在浏览器本机生成，不上传。下载使用原生 `Blob` + `<a download>`，
文件名由注入时钟决定（UTC，`gomoku-lab-<kind>-YYYYMMDDHHmmss.json`）。

## 2. 导入流程

`选择文件 → 读取大小 → 解析 → 严格校验 → 预览 → 选择恢复项 → 确认 → 写入 → 结果`

预览至少显示：格式/版本、棋谱总数、可导入数、重复数、无效数、无效原因（前三条）、
备份里包含哪些可选段。**解析失败、校验失败、用户取消都在写入之前，零写入。**

本阶段**只提供合并，不提供替换**。UI 里没有「删除后插入」的假恢复：
危险操作宁可不做，也不拿它冒充完整恢复。

### 合并语义

| 数据 | 默认 | 语义 |
| --- | --- | --- |
| 棋谱 | 总是合并 | 按规范化内容去重；只新增，不删除现有记录；损坏/未结束记录跳过并计数 |
| 学习/残局进度 | 勾选（文件有时） | 完成项取并集；本地已有进度时**保留本地当前位置**，不被旧备份顶走 |
| 显示偏好 | 不勾选 | 主题、坐标、音效；默认不改本地设置 |
| 上次对局会话 | 不勾选 | 可能已结束；明确提示「会替换当前保存的对局」；默认关闭 |
| 自定义局面 | 勾选（文件有时） | 按盘面/下一手/已知手顺去重；不删除现有局面 |

进度合并的「本地已有进度」判据是：完成课程/残局非空，或 `lastVisited` 非 null。
完全空的浏览器恢复备份时才采用备份里的 `lastVisited/lastView`——否则恢复数据
不该顺带把用户当前页面切走。

## 3. 事务与失败语义

- **棋谱批量写入**：一个 `readwrite` 事务内 `getAll` 去重 + 逐条 `add`。
  任何一条失败/事务中止 → 整笔回滚，旧棋谱不受影响。
- **局面库降级**（打不开或本次会话只有内存局面）：**拒绝生成完整备份**，提示先恢复 IndexedDB；
  不会静默导出一段空局面。
- **IndexedDB 打不开**（隐私模式/被禁用）：退回内存兜底，结果 `storage='memory'`，
  界面明确说「本次会话可用，刷新后可能丢失」；此时 `list()` 也走同一份内存兜底。
- **打开成功但事务失败**（典型是配额）：整笔回滚，`storage='failed'`，新记录 0 条；
  **不写内存**——否则 `list()` 仍读 IndexedDB，界面会说「本次会话可用」却一条也看不到。
  界面明确说「没有写入任何棋谱；旧数据未变」。
- **进度**：在棋谱事务之后单独写入；失败时结果分项标「失败」，已导入的棋谱保留。
  **不把部分成功显示成全部成功。**
- **偏好/会话**：写 `localStorage`（zustand persist / 会话键），与 IndexedDB
  不在同一个事务里；失败会分项标「失败」。文档不承诺跨存储原子性。
- **导入取消**：只在 React state 里预览，没有任何写调用。
- **重复导入**：内容去重后 `imported=0`，结果如实说「跳过重复 N 条」。

## 4. 恢复后怎么验证

1. 刷新页面，棋谱仍在列表里。
2. 点开棋谱，把时间轴拖到末手，棋子数与手数一致。
3. 若恢复了进度，进「教学」看已完成数；进「残局」看已解题数。
4. 若恢复了会话，进「对战」看棋盘是否就是备份里的局面。
5. 若恢复了偏好，看主题/坐标/音效是否变化。

## 5. 安全边界

- 文件是**不可信输入**：不执行脚本、不 `eval`、不按字段名猜含义。
- 先检查大小与嵌套深度，再 `JSON.parse`；限制局数、手数、字符串长度。
- 未知字段只警告；未来版本明确拒绝。
- 不导出分析缓存、账号、IP、浏览器指纹或构建环境。

## 6. 已知限制

- 完整备份 v2 已包含自定义局面；v1 备份仍可导入，但其中没有局面段。
- 没有「替换/清空后恢复」；只有保守合并。
- 没有压缩；10 MiB 上限对应约数千局，超出请分批导出。
- 备份不包含 `localStorage` 之外任何浏览器状态（如未完成的分析）。
- 关闭页面前的写入仍是尽力而为；导出是用户主动动作，不依赖 unload。
- 跨浏览器/设备迁移通过文件完成，不做云同步。
